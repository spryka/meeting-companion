# ADR-0002: Изолированный Swift worker транскрибации

Status: accepted
Accepted: 2026-11-02
Date: 2026-10-30
Supersedes: none

## Context

Meeting Companion уже отделяет Python-транскрибацию subprocess от записи и UI.
Переход к Swift/MLX должен убрать Python/uv из поставки без переноса моделей
в процесс захвата. Готовые Swift-реализации имеют несовместимые dependency ranges
и различающиеся профили весов. Их пригодность ещё проверяется.

## Decision

Предлагается сохранить процессную границу: bundled Swift executable обрабатывает
одну запись и завершается. MLX, GPU state и модели принадлежат этому процессу.
UI запускает его, читает существующие progress events, ожидает exit и управляет
отменой. Подготовка весов явная, inference использует локальные pinned snapshots.
Архитектуры моделей берутся из готовых реализаций, без самостоятельного порта.

Внутри записи worker обрабатывает обе дорожки последовательно каждой моделью:
одна загрузка весов на этап, чистое inference state для каждого источника,
освобождение модели перед следующей. MLX allocator cache не заменяет управление
объектами моделей. Порядок этапов и проверки описаны в design/specs change.

Подключение к приложению допускается после model/full-pipeline comparison.
Результат каждой обработки остаётся отдельной неизменяемой версией согласно
ADR-0001. Python baseline сохраняется вне test bundle. Capture/AEC DSP не меняются.

## Alternatives

- In-process Swift/MLX: меньше IPC, но общий lifecycle, GPU faults и память с UI.
- XPC service: изоляция сохраняется, появляется лишний service lifecycle.
- Несколько executables с разными MLX: возможный обход конфликта версий,
  но больше упаковки, IPC и проверки ресурсов. Пока не требуется.
- Python внутри bundle: не выполняет цель отсутствия Python и пакетов.

## Consequences

Exit worker освобождает его адресное пространство, сохранность recorder не зависит
от модели. Появляется проверяемый контракт process/progress/cancellation и
обязанность упаковать Metal resources, dylibs и notices каждого dependency.
Загрузка каждой нужной модели остаётся на каждую запись. Общие веса требуют
проверок независимости state и прогресса. Выигрыш скорости/памяти не гарантирован;
эффект расписания измеряется отдельно от перехода на Swift.

Владелец разрешил начало реализации в этой процессной границе 2026-11-02
после актуализации плана под текущий редактор. Air 8 GiB исключён из приёмки,
прежний перечень модельных расхождений снят как неактуальный; это не меняет
процессное решение. Статус accepted не означает успешные product/model checks,
готовую поставку или разрешение установки/релиза.
