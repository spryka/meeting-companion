# Эксперимент WebRTC AEC3

Статус на 2026-10-22: мягкий нативный вариант встроен как выключенная
по умолчанию галка «Эхоподавление микрофона» в настройках записи.
Обработка выполняется после записи, перед распознаванием, без доступа к устройствам.
Apple Voice Processing удалён после неудачного живого UAT. Обычная запись
микрофона, выбор устройства, мьют и исходные дорожки сохраняются.

## Что пробуем

Используем Google WebRTC AEC3 через экспериментальную Python-обёртку
`aec-audio-processing==1.0.0.dev9`. В её исходниках `src/audio_processing_module.cpp`
включён `echo_canceller.enabled`, `mobile_mode=false`; вложенный WebRTC
`audio_processing_impl.cc` выбирает `EchoCanceller3`. На macOS 15+ ARM64
есть wheel для CPython 3.12. Это сторонняя обёртка, а не библиотека Google
для распространения приложения. Приложение использует собственный C++ helper
с той же закреплённой нативной библиотекой и соответствующими заголовками из sdist.
`scripts/build-aec.py` проверяет SHA-256 архива, собирает helper и копирует лицензии
в поставку. Python-обёртка нужна только старому отдельному стенду.

- AEC включён, NS, AGC и VAD выключены; состояние проверяется перед запуском.
- Берём синхронные raw WAV микрофона и системного звука, по 10 мс.
- Системный звук — опорный сигнал, результат — новая копия микрофона.
- Стенд не открывает аудиоустройства, не меняет маршруты и не проигрывает звук.
- Исходники, общий M4A и транскрипты не перезаписываются. Длина и тишина сохраняются.
- Несовпадающие таймлайны и другой формат отклоняются; задержка задаётся явно.

## Запуск

Из корня репозитория, сначала синтетическая проверка:

```sh
uv run --quiet --python 3.12 --with aec-audio-processing==1.0.0.dev9 --with numpy \
  python scripts/probe-webrtc-aec.py check
```

Потом исходники **обычной** записи без Apple-обработки, PCM16/mono/16 kHz:

```sh
uv run --quiet --python 3.12 --with aec-audio-processing==1.0.0.dev9 \
  python scripts/probe-webrtc-aec.py process \
  /path/raw/meeting.host_record.wav /path/raw/meeting.remote_record.wav \
  /path/experiment/host-aec.wav --delay-ms 0
```

Первый запуск скачивает библиотеку из PyPI. Аудио обрабатывается локально.
Python-обёртка не нужна приложению. Нативные helper, dylib и third-party notices
поставляются внутри bundle; при сборке архив зависимости скачивается и кэшируется.
Задержка — время от опорного системного звука до захваченного микрофона;
нулевая величина — исходная гипотеза для сохранённых синхронных дорожек.
При слабом результате сравниваем несколько обоснованных задержек на одном фрагменте.

## Что ещё проверять в UAT

1. Короткая запись без Apple: собеседник через динамики, затем голос владельца
   поверх собеседника, пауза, смена вывода на наушники. Вход — выбранный микрофон ноутбука.
2. На копии сравнить эхо, сохранность собственного голоса, начало/конец слов,
   артефакты и распознавание. Синтетическое подавление эха не подтверждает качество речи.
3. Проверить переключение устройств, нагрузку CPU/RAM и длинную запись.
   Лицензии уже включены в поставку; эти проверки нужны до стабильного релиза.

Офлайн-AEC не улучшает звук, который собеседники получают в Телемосте:
он меняет только нашу копию микрофона. Сам стенд не включает двусторонний
аудиограф и не вмешивается в звук звонка.

Если AEC не даёт устойчивого результата, следующий отдельный эксперимент —
поиск дублей между дорожками по времени и тексту. Нельзя удалять одинаковые
фразы без временного совпадения и подтверждения эха: это могут быть две
настоящие реплики. Сначала журнал кандидатов и сравнение копии транскрипта;
исходный GigaAM и аудио сохраняются.

## Проверка на реальных записях, 2026-10-22

Исходники сохранены; все варианты обрабатывались офлайн в отдельной папке эксперимента.
Результаты ниже относятся к конкретным записям, а не к качеству AEC3 в целом.

### Известный текст, запись 16:28:23

Длительность 74,46 с. Два чтения поверх видео (25–40 и 40–57 с), затем чтение
в паузе (58–74,46 с). Первые 25 с — контроль видео без голоса владельца.
Заданный текст содержит 19 слов; ошибки считаются относительно задания,
без ручной проверки того, насколько точно оно было прочитано.

| Вариант | Ошибки, первое / второе чтение | Текст видео на контрольном участке |
| --- | --- | --- |
| Исходный микрофон | 29 / 18 | Есть |
| Python-обёртка, обычный AEC3 | 0 / 1: пропущено «микрофона» | Нет |
| Нативный AEC3, штатные параметры | 0 / 0 | Нет |
| Нативный AEC3, мягкое подавление | 0 / 1: «микрофона» → «микрофон» | Нет |
| Только линейное вычитание | 0 / 0 | Есть, длинный связный текст видео |

Распознаватель — один и тот же GigaAM v3 RNNT, без Parakeet, VAD и диаризации,
с одинаковыми границами фрагментов. Ошибки — расстояние Левенштейна по словам
после удаления пунктуации и нормализации регистра/ё. В паузе заданный текст
распознаётся полностью во всех вариантах; вводное «я поставил на паузу»
произнесено отдельно и в оценку двух чтений не входит.

На контрольных 6–20 с снижение RMS относительно исходного микрофона:
обычный AEC3 около 28,3 дБ, мягкий — 24,4 дБ, линейный — 12,2 дБ.
Это изменение уровня всей дорожки на выбранном участке, не измерение ERLE
по изолированному эталону эха. Отсутствие текста на контрольном участке
не гарантирует отсутствия остаточного эха на всей записи.

### Регрессия: начало слова, запись 12:38:47

Пользователь услышал потерю «пара-» в «параллельно» около 52 с после обычного AEC3.
Восемь задержек (0, 10, 20, 31, 50, 90, 150, 300 мс) в Python-обёртке
не дали надёжного распознавания слова. Нативный штатный режим тоже не распознал
фразу на 48–57 с. В мягком режиме GigaAM распознал «сейчас говорю параллельно»;
на контрольных 16–30 с текст видео не распознался. Линейный выход сохранил
фразу, но вместе с большим количеством текста видео. Прослушивание пользователем
новых вариантов ещё требуется: ASR сам по себе не доказывает сохранность согласных.

### Что менялось в нативном стенде

Использована та же `libwebrtc-audio-processing-2.dylib` из закреплённого wheel
и соответствующие заголовки из sdist (SHA-256
`46dc45181de1b19cf9a76d2fe3c9107498d5233ea9f7b334e7801b89cec2e090`).
Настройки задаются до `AudioProcessingBuilder.Create()`, `EchoCanceller3`
создаётся через собственную `EchoControlFactory`, включён экспорт линейного
выхода. NS и оба AGC отключены, кадры 10 мс, mono/16 kHz; внешняя задержка 0 мс.
Это другой способ инициализации, поэтому нативный штатный вариант показан
отдельно от исходной Python-обёртки; причина различий между ними не установлена.

В мягком варианте изменены только следующие поля `EchoCanceller3Config`:

```text
suppressor.dominant_nearend_detection.enr_threshold = 0.75
suppressor.dominant_nearend_detection.trigger_threshold = 1
suppressor.dominant_nearend_detection.snr_threshold = 10
suppressor.normal_tuning.mask_lf.enr_transparent = 0.4
suppressor.normal_tuning.mask_lf.enr_suppress = 0.5
suppressor.nearend_tuning.mask_lf.enr_transparent = 2.0
suppressor.nearend_tuning.mask_lf.enr_suppress = 2.1
suppressor.nearend_tuning.mask_hf.enr_transparent = 0.3
suppressor.nearend_tuning.mask_hf.enr_suppress = 0.5
```

Дополнительный вариант только с тремя изменениями детектора своего голоса,
без изменений масок подавления, на старом фрагменте распознал «говорю парадильно»;
его недостаточно, чтобы считать проблему решённой.

Вывод: линейное вычитание отдельно пока не подходит — остаточное видео попадает
в транскрипцию. Мягкий режим — кандидат для дальнейшего прослушивания и тестов,
поскольку улучшил старый проблемный фрагмент. По одной новой записи штатный
нативный режим дал меньше ошибок, но старую регрессию не прошёл.
В приложение встроен мягкий вариант. Не проверены длительная обработка
и устойчивость на других голосах/громкости. Живой аудиограф не меняется.

### Отсутствие акустического эха

В дополнительной офлайн-симуляции взят чистый голос из паузы (58 с и далее),
а опорой стало постороннее видео. После AEC распознавание пропустило
«Параллельно», которое есть в исходном распознавании. Это не проверка реальных
наушников и не доказательство удаления звука, но оснований рекомендовать
постоянно включённый AEC нет. Поэтому используем ручную галку только для динамиков.
При полностью нулевой опоре обход проверен на побитовое совпадение микрофона.
