# Transcript Document Fixtures (JSON v1)

Синтетические эталонные наборы данных (fixtures) формата структурированного документа расшифровки `result.json` (JSON v1).
Предназначены для совместного использования Python-конвейером (`transcription/`) и будущей Swift-реализацией (`MeetingCompanionCore` / `MeetingCompanionApp`) для обеспечения идентичной сериализации, десериализации и валидации.

## 1. Спецификация формата JSON v1

Формат структурированного документа расшифровки фиксирует результат распознавания, baseline, состояние моделей и доступность аудиомикса согласно `openspec/changes/transcript-editor/design.md` и `specs/transcript-document/spec.md`.

### Обязательные поля верхнего уровня

- `schemaVersion` (`int`): Версия схемы. Для текущего формата строго равна `1`.
- `resultID` (`string`): Непустой уникальный строковый идентификатор версии результата (например, `res_valid_parakeet_off`).
- `createdAt` (`string`): Временная метка создания в формате RFC 3339 с указанием часового пояса (например, `2026-10-29T12:00:00+03:00`).
- `sources` (`array[object]`): Список аудиоисточников записи.
  - `id` (`string`): Уникальный идентификатор источника: `"host"` (микрофон) или `"remote"` (системный звук).
  - `originalAudioPath` (`string`): Относительный путь к исходному аудиофайлу относительно каталога встречи (например, `"raw/meeting.host_record.wav"`).
  - `recognitionAudioPath` (`string`): Относительный путь к файлу, фактически поданному в модель распознавания (для AEC outcome=`applied` — путь к неизменяемой копии версии, для остальных — исходный микрофон).
  - `diarizationStatus` (`string`): Статус диаризации: `"completed"`, `"disabled"` или `"failed"`.
  - `detectedVoiceCount` (`int` или `null`): Число обнаруженных моделью диаризации голосов (целое `0`..`8` либо `null`). Значение `0` означает подтверждённое отсутствие голосов; `null` — число неизвестно (диаризация выключена или завершилась сбоем). Фиксируется до назначения спикеров словам.
  - `correctionStatus` (`string`): Статус терминологической коррекции источника: `"disabled"`, `"completed"` или `"failed"`.
- `speakers` (`array[object]`): Список спикеров, обнаруженных или назначенных в рамках данной версии.
  - `id` (`string`): Уникальный строковый ID спикера внутри документа (например, `"spk_h1"`).
  - `sourceID` (`string`): Источник (`"host"` или `"remote"`).
  - `localID` (`int`): Положительный целочисленный идентификатор (локальная метка голоса внутри источника, `1`..`N`).
  - `displayNumber` (`int`): Положительный уникальный номер для интерфейса и экспорта. Номера микрофона начинаются с `1`; номера системного звука смещаются на максимальный локальный номер микрофона (минимальное смещение 1, аналогично правилу `merge_sources`).
- `words` (`array[object]`): Итоговые распознанные слова после возможной коррекции.
  - `id` (`string`): Уникальный строковый ID слова.
  - `speakerID` (`string`): Ссылка на `id` из `speakers`.
  - `start` (`float`): Время начала слова в секундах (`>= 0`, конечное число).
  - `end` (`float`): Время окончания слова в секундах (`>= start`, конечное число).
  - `text` (`string`): Текст слова.
- `turns` (`array[object]`): Реплики (абзацы), объединяющие последовательные слова одного спикера.
  - `id` (`string`): Уникальный строковый ID реплики.
  - `speakerID` (`string`): Ссылка на `id` из `speakers`.
  - `start` (`float`): Время начала реплики (`<=` начала первого слова).
  - `end` (`float`): Время окончания реплики (`>=` конца последнего слова).
  - `wordIDs` (`array[string]`): Список идентификаторов слов `words`, входящих в реплику. Каждое слово входит ровно в одну реплику. Все слова принадлежат тому же `speakerID`. Текст реплики формируется конкатенацией слов через один пробел.
- `baselineWords` (`array[object]`): Исходные слова базовой модели GigaAM до терминологической коррекции Parakeet.
  - Структура объектов совпадает со структурой `words` (`id`, `speakerID`, `start`, `end`, `text`), но ID находятся в собственном пространстве.
  - При выключенном (`"disabled"`) или неуспешном (`"failed"`) Parakeet текст и интервалы слов совпадают с итоговыми `words`.
- `aec` (`object`): Состояние эхоподавления микрофона.
  - `requested` (`boolean`): Было ли запрошено эхоподавление (`--echo-cancel`).
  - `outcome` (`string`): Результат: `"disabled"`, `"applied"`, `"bypassed"` или `"failed"`.
- `playback` (`object`): Доступность готового синхронизированного аудиомикса.
  - `status` (`string`): `"ready"` или `"unavailable"`.
  - `mixPath` (`string` или `null`): Относительный путь к миксу версии. Для `"ready"` обязателен непустой путь; для `"unavailable"` строго `null`.
- `warnings` (`array[object]`): Список предупреждений, зафиксированных при обработке.
  - `code` (`string`): Машиночитаемый код предупреждения (например, `"speaker_limit"`, `"correction_failed"`, `"playback_mix_failed"`, `"diarization_failed"`).
  - `sourceID` (`string` или `null`): `"host"`, `"remote"` или `null` (если относится ко всей записи).
  - `message` (`string`): Понятное пользователю сообщение без раскрытия абсолютных путей операционной системы.
- `context` (`object` или `null`): Снимок метаданных календаря (при наличии):
  - `title` (`string`, опционально): Название встречи.
  - `startAt` (`string`, опционально): Время начала в RFC 3339.
  - `timeZone` (`string`, опционально): Часовой пояс.
  - `agenda` (`string`, опционально): Описание/повестка встречи.
  - `attendees` (`array[string]`, опционально): Список приглашённых участников.

## 2. Опись эталонных фикстур (Valid Fixtures)

1. **`valid_parakeet_off.json`**:
   - Parakeet выключен (`correctionStatus: "disabled"`).
   - Baseline GigaAM и итоговые слова полностью идентичны по тексту и таймкодам.
   - Короткие фразы, уникальные `displayNumber` (микрофон 1, система 2).
   - Аудиомикс готов (`playback.status: "ready"`), календарный контекст заполнен.

2. **`valid_parakeet_on.json`**:
   - Parakeet успешно применён (`correctionStatus: "completed"`).
   - `baselineWords` содержит исходный текст GigaAM (`"кубернетес"`).
   - `words` содержит скорректированный термин Parakeet (`"Kubernetes"`).
   - Независимые пространства ID для `baselineWords` и `words`.

3. **`valid_partial_failure.json`**:
   - Частичный сбой коррекции: на host коррекция успешна (`"completed"`), на remote завершилась сбоем (`"failed"`).
   - Remote сохраняет baseline GigaAM в итоговом тексте.
   - `warnings` содержит код `"correction_failed"` для источника `"remote"`.
   - Дополнительно иллюстрирует сбой подготовки микса (`playback.status: "unavailable"`, `playback.mixPath: null`, `aec.outcome: "failed"`).

4. **`valid_overlaps_identities.json`**:
   - Одновременная речь: перекрывающиеся временные интервалы слов и реплик между host и remote. Временные шкалы не смещены искусственно.
   - По два спикера на каждом источнике (локальные ID 1 и 2).
   - Отображаемые номера строго уникальны: host получает `1` и `2`, remote — `3` и `4`.
   - Внутренние ключи сохраняют привязку `sourceID`/`localID`.

5. **`valid_empty_voices.json`**:
   - Пустой источник: дорожка remote содержит тишину, где модель диаризации успешно подтвердила отсутствие речи (`detectedVoiceCount: 0`, `diarizationStatus: "completed"`).
   - Массивы слов и реплик для remote пусты; выдуманные реплики отсутствуют.

6. **`valid_unknown_voices.json`**:
   - Неизвестное число голосов: на host диаризация отключена (`diarizationStatus: "disabled"`, `detectedVoiceCount: null`), на remote завершилась ошибкой (`diarizationStatus: "failed"`, `detectedVoiceCount: null`).
   - Назначены запасные метки спикеров без ложного утверждения об обнаруженных голосах.

## 3. Опись негативных фикстур (Negative Fixtures для валидатора)

Предназначены для будущего валидатора документов (задача 1.2a в Python и 1.3 в Swift):

1. **`invalid_schema_version.json`**: `schemaVersion: 2` (неподдерживаемая версия схемы).
2. **`invalid_duplicate_ids.json`**: Дублирование идентификатора слова `w_duplicate` в массиве `words`.
3. **`invalid_broken_references.json`**: Реплика ссылается на несуществующий `w_missing_123` в `wordIDs`.
4. **`invalid_intervals.json`**: Некорректный временной интервал слова (`start: 2.0, end: 1.0`, `start > end`).
5. **`invalid_path_traversal.json`**: Путь к аудиофайлу выходит за пределы каталога записи (`"../../sensitive/host.wav"`).

## 4. Границы задачи 1.1 и открытые аспекты

- В RED-блоке 1.1 тесты генерации через `transcribe-recording.py:main()` падали на отсутствии `result.json` после успешного создания TXT (см. verification-1.1.md).
- После GREEN-блока 1.2 те же тесты обычно проходят и выполняют проверки содержимого документа. `expectedFailure`/`xfail` не используются.
- По согласованию негативные JSON переданы в задачу 1.3: отклонение дубликатов ID, неверных ссылок, версии, интервалов и путей нужно проверить через Swift-границу чтения до её реализации. Ошибка импорта не считается RED. Уже существующее отклонение неверных входных ASR-интервалов проверено отдельно как GREEN-регрессия, а не как проверка JSON-валидатора.
