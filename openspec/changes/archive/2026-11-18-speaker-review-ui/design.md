## Goals / Non-Goals

Цель — найти и прослушать любой исходный голос без прокрутки полного текста, назначить имя и продолжить разбор. Быстрая правка сохраняет область одной реплики/остатка голоса. Весь путь работает offline по уже сохранённому контексту.

Автоопределение личности — отдельная работа. Не добавлять модели, enrolment, confidence, статусы автоматического распознавания, personID, объединение исходных голосов, миграцию JSON или постоянный журнал проверки. Один человек может соответствовать нескольким голосам; повторное имя разрешено вручную.

## Decisions

### 1. Два входа, связанный сценарий

Имя у реплики открывает существующую локальную модалку. По умолчанию выбрана одна реплика. Вторая область — текущая и последующие реплики того же source/voice в document.turns. До явного подтверждения показываются имя, источник/голос, число изменений и замен ручных имён, до трёх примеров. Cancel не пишет; неизменённое имя — no-op.

Ссылка «Прослушать все реплики этого голоса (N) →» закрывает локальную модалку и открывает выбранный исходный голос в общем разборе. Это не сохранение: введённое имя переносится как черновик; область меняется на всю группу и показывается новый preview. Сохранение требует нового явного действия.

Количество говорящих в шапке открывает общий разбор. При первом входе выбран первый голос, у которого не все реплики имеют ручное имя; если таких нет — первый голос. В пределах открытой session повторный вход сохраняет выбранный голос. Из локальной модалки выбор всегда задаёт её исходный голос.

### 2. Размещение и возврат

Общий разбор заменяет правую область workspace, без нового окна и второго writer. Библиотека остаётся слева при достаточной ширине. «К транскрипту» возвращает сохранённую позицию чтения; «В транскрипте» у фрагмента возвращает к конкретной реплике с фокусом. Название, дата/время, длительность, статус, приглашённые, существующие действия и плеер сохраняются на экране транскрипта. Приглашённые не исчезают при назначении имени.

На узкой панели список голосов и детали показаны поочерёдно. «Все говорящие» открывает список; выбор возвращает детали. В шапке разбора остаются название и возврат к транскрипту; экспорт, More и новая запись не конкурируют с ними за ширину. Эти существующие действия не удаляются из приложения. Размер считается по доступной ширине правой панели, а не только окна: в HTML это container queries 760/640/420 px; в Swift реализовать эквивалент по fitting size и сохранять текущую native узкую навигацию библиотеки.

### 3. Идентичность и построение списка

Ключ выбора: recording identity + resultID + sourceID/localID (либо speakerID, разрешённый в эту пару). Не использовать отображаемое имя, номер в UI или индекс списка как identity. Группы строятся из текущего документа, учитывая все его реплики; порядок — первое появление в document.turns. Внутри группы порядок document.turns сохраняется, в том числе при одинаковых start. Реплики с тем же localID в другом source — другой голос. Голоса с нулём реплик не показываются.

Список показывает effective имя, если вся группа имеет одно назначенное имя; иначе исходный Speaker N. Рядом — источник, число реплик и состояние. Группа с различающимися ручными именами не объединяется: источник остаётся тот же. У позднего голоса показано время первой реплики.

### 4. Назначение всей группе

Текущие ручные displayName сохраняются по умолчанию; меняются только реплики без manual displayName. Флаг «Заменить ранее назначенные имена (N)» сброшен при выборе другого голоса. Включение разрешает заменить manual имена только в выбранной группе. Текстовые overrides сохраняются при любом назначении имени.

Модель выдаёт preview текущей группы через существующий previewGroupAssignment. UI отдельно считает реально меняющиеся effective имена для введённого имени: affectedTurnsCount Core включает допустимые targets и не всегда равен числу видимых изменений. Не подменять service preview самостоятельно собранным объектом.

Перед записью проверить recording/result/session/draft identity, актуальность preview/revision и введённого имени; поменяв имя или флаг, пересчитать preview и payload подтверждения. Для операции использовать assignSpeakerName(preview:displayName:), затем перечитать строки и обновить списки/счётчик/подсказки. Переходить к следующему только после успешного сохранения. При нуле реальных изменений не вызывать запись; разрешён переход без фиктивной revision.

### 5. Навигация по голосам и состояние проверки

Состояния «Не назначен», «Имя назначено», «Разные имена», «Пропущен» — presentation текущего результата. «Не назначен» включает частично назначенную группу до её просмотра; существующее имя любой отдельной реплики видно справа. Для уже полностью назначенных групп начальное состояние считается разобранным, что не означает автоматическую валидацию личности.

«Разобрано X из N» включает разобранные и явно пропущенные группы. Основное действие сохраняет выбранную группу и выбирает следующую неразобранную/непропущенную в порядке списка с однократным переходом к началу. «Пропустить» ничего не пишет; «Следующий» у уже разобранного голоса ничего не меняет. Любой голос доступен через список и после завершения. Когда следующих нет, появляется «Разбор завершён» с числом проверенных и пропущенных и возвратом к транскрипту. Закрытие не требует пройти всех.

Пропуски, прогресс и черновики — память review session, отдельно в edits.json не сохраняются. При повторном открытии сохранённые имена читаются с диска, состояние обхода выводится заново. Новые persistence keys и schemaVersion не нужны. Переход с неразрешённым вводом использует existing draft/admission policy; нельзя незаметно писать или терять draft при смене записи, retry, close или внешней команде.

### 6. Календарные подсказки

Использовать только сохранённые attendees выбранной записи. При открытии/обновлении обоих редакторов вычислять назначенные manual displayName по всем репликам текущего результата, включая частично назначенные группы. Ключ сравнения: Unicode NFC, обрезка краевых пробелов, регистронезависимое сравнение. Отфильтровать совпадающие calendar names и повторные подсказки; сами сохранённые имена не переписывать этой нормализацией.

Если последнее назначение имени изменено на другое, прежнее имя снова доступно при следующем вычислении. Совпадение строк не доказывает identity и не запрещает повторный ручной ввод. Запрос разрешений, EventKit refresh и сеть на editing path не добавляются. Отсутствие/исчерпание подсказок объясняется, поле остаётся доступно. Список «Приглашены» в описании встречи не фильтруется.

### 7. Прослушивание фрагментов

Проигрывать interval выбранной реплики из микса current result через текущий transport/controller. Кнопка: seek к start, затем play только после подтверждённого успешного seek. Pause действует на тот же player. Для окончания фрагмента добавить минимальное состояние верхней границы в существующий playback путь; публичный API сейчас не имеет playSegment. Не создавать вторую аудиосессию или отдельный media файл.

На достижении end остановить фрагмент; автоматический переход к другой реплике отсутствует. При смене голоса, уходе в текст, закрытии или смене результата отменить interval и устаревший seek callback. Нулевой/некорректный interval не запускается. Общая шкала, overlap и один reading focus сохраняются; микс может включать одновременно другие голоса. Это не изоляция конкретного человека. Недоступное аудио блокирует только прослушивание, текст и разрешённые правки доступны. Не подменять микс другой версией/источником.

### 8. Сохранение и ошибки

Использовать текущий result.json как immutable recognition и edits.json для displayName overrides. Сохранить revision/CAS, writer lock, containment, current-result/draft guards. Пока идёт запись, повторный Confirm и конфликтующие переходы заблокированы. UI считает группу сохранённой только после завершения commit.

Ошибка записи/конфликт preview/смена current не запускают автоматический retry, rebase, переключение версии, новый writer или fallback. Показать ошибку, сохранить ввод и прежнее saved состояние, не увеличивать прогресс. Обычный Save failure можно явно повторить по существующей policy. При устаревшем current требуется Cancel и повторное открытие записи; старый preview не использовать повторно. Файлы/исходный текст не удалять. Для read-only/legacy представления общий разбор недоступен с понятной причиной.

## Risks / Trade-offs

Два входа сохраняют быстрый сценарий и добавляют массовый; одинаковые подсказки и общий переход уменьшают различия между ними. Имя не служит доказательством личности. Сессионный прогресс не равен постоянному журналу валидации. Пользователь может вернуться и исправить только одну ошибочную реплику даже после назначения всей группе.

HTML содержит нормальные демопереходы и не является native storage/error implementation. Все native guards обязательны; отсутствие в демо failure injection не разрешает их убрать. Детальное покрытие и непроверенные границы указаны в reference/coverage.md.

## Migration Plan

Миграции данных нет. Перенести OpenSpec change в свежий checkout, сверить drift, реализовать native presentation и минимальные дополнения текущего playback. Существующие назначение, экспорт, редактирование текста и toolbar routes сохранить. При откате UI сохранённые edits.json читаются прежним редактором. Исторические результаты и прежние changes не удалять.

## Validation Strategy

TDD на группировку/изоляцию источников, single/remaining/group scopes, ручные назначения, календарную фильтрацию, no-op, preview/CAS failures и поздние callbacks. Playback — fake transport для interval end/seek/pause/cancel. Native UAT — общий workspace, узкое окно, длинные имена, keyboard/VoiceOver, скролл и длинная встреча с поздним голосом. Проверки реализации перечислены в tasks.md и пока не выполнены.
