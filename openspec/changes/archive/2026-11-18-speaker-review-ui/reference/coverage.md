# Соответствие SDD и кликабельного эталона

Эталон `index.html` — копия актуального `speaker-review.html` этого проекта, включающая восстановленное окружение, адаптивную компоновку и оба входа назначения. Основной макет и копия обновлены вместе при подготовке SDD. Это привязка к текущим файлам, не обещание автоматической синхронизации последующих изменений.

## Карта сценариев

| Требования | Как увидеть в макете | Что показано |
| --- | --- | --- |
| S02, W04.11 | Нажать имя у любой реплики | «Сменить спикера», имя, область one/remaining, target/source/count, примеры и явное подтверждение |
| S02 | В локальном окне выбрать «Прослушать все реплики этого голоса (N) →» | Переход к той же исходной группе, введённое имя переносится без сохранения |
| S01, S03 | Нажать «7 говорящих» | Общий экран справа; библиотека остаётся на широкой компоновке |
| S01 | Выбрать Speaker 7 | Поздний голос, первая реплика 1:12:04, все три реплики сразу доступны |
| S04 | Выбрать Speaker 5 | Одна из реплик уже назначена Алексею Морозову; без checkbox это имя сохраняется |
| S04 | Включить «Заменить ранее назначенные имена» | Меняется preview и текст основной кнопки; область — вся выбранная группа |

## Привязка к элементам

- `#openReview` — общий вход; `[data-edit-speaker]` — точечный вход. Эти пути различаются.
- `#localSpeakerDialog` — точечная правка; `#openLocalGroup` — связующий переход.
- `#voiceList`, `#turns`, `#speakerName`, `#overwrite`, `#assignVoice` — общий разбор.
- `#transcriptIntro` — полное описание с приглашёнными; его данные не фильтруются вместе с suggestions.
- `availableCalendarNames()` — общая фильтрация двух редакторов.
- `localSpeakerTargets()` — одна реплика либо выбранный source/voice от anchor до конца. Модель передаёт сюда только реплики исходного голоса.
- `.main-pane` container queries — адаптация по ширине панели, включая случай видимой библиотеки.

## Что макет не доказывает

S05/S10: filesystem commit, lock/CAS, current-result/draft admission, read-only/unsupported routes и async race outcomes проверяются на native реализации. Для них в SDD есть обязательные сценарии, но нет фиктивных HTML success/error симуляций.

S08: настоящий микс, качество seek/паузы/границы интервала и слышимость overlap требуют native playback проверки. HTML содержит синтетические тексты и таймер; он не изолирует звук говорящего и не подключён к AVPlayer.

S06: после reload браузера имена теряются. В приложении имена должны сохраняться существующим edits.json; только прогресс обхода и skip остаются сессионными.

Библиотека/поиск/плеер/toolbar нужны для завершённого контекста. Поиск фильтрует показанные демозаписи; другие записи и общие действия показывают демопояснение. Это не спецификация нового поиска, настроек, экспорта или формы записи.

В эталоне 7 голосов; кейсы 1/16 голосов, пустого/legacy результата, очень длинных имён, короткого окна и native VoiceOver перечислены в tasks как проверки реализации, а не заявлены пройденными.

## Статус сверки

Сопоставление выполнено по исходному HTML и документам, включая подписи, обработчики двух входов, source/voice области и переходы. Визуальный браузерный прогон, native UAT, OpenSpec validation и Swift build/test на этом этапе не выполнялись. Матрица не является PASS независимого ревью.

Если при реализации принято менять согласованное поведение или подписи, обновить specs, design, этот эталон и матрицу вместе до приёмки. Не переносить машинные пути, реальные записи и календарные данные в fixtures/коммиты.
