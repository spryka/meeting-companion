## 1. Задокументированный маршрут (Walkthrough)

### 1.1 Открытие окна из истории (`pathhistoryopen`)

- Пользователь выбирает запись в истории и нажимает кнопку «Открыть расшифровку».
- Координатор окон (`TranscriptReviewWindowManager`) поднимает окно для выбранной записи. При повторном нажатии активируется и выводится на передний план уже открытое окно без создания дубликатов.
- Переход из капсулы записи («Открыть результаты») ведёт в окно истории, из которого доступна расшифровка.

### 1.2 Режимы окна и закрепление версий (`validversion pinned/legacy text`)

- Для валидного структурированного документа `result.json` окно открывается в режиме `.review` с закреплением открытой версии (`activeResultID`). Новые фоновые проходы распознавания не сбивают открытый результат.
- В шапке окна доступен селектор опубликованных версий с датой/временем и идентификатором. Переключение версии транзакционно синхронизируется с историей.
- Уточнение Sol1 секции 5: список `versions` читается только при создании модели окна; после retry открытое окно остаётся pinned, но не обновляет селектор. Сохранить черновики, закрыть окно и открыть заново из истории, затем явно выбрать версию. Повторный клик без закрытия только фокусирует окно. Legacy-артефакт — `<basename>.sources.transcript.txt`, не экспортный `transcript.txt`.
- Старые записи без структурированного JSON или записи без опубликованных версий открываются в безопасном текстовом режиме `legacyReadOnly` («Только чтение») без плеера, редактирования и экспорта. Повреждённые структурированные данные не скрываются тихим переключением на TXT.

### 1.3 Воспроизведение и следование (`playback followmanual`)

- Воспроизведение аудиомикса выбранной версии: кнопки «Воспроизвести» / «Пауза», ползунок перемотки и кнопки таймкодов `[HH:MM:SS]`.
- Автоскролл синхронно центрирует текущую звучащую реплику и подсвечивает одновременные реплики на перекрытиях.
- Ручная прокрутка временно приостанавливает следование; кнопка «Вернуться к воспроизведению» мгновенно возвращает фокус к текущей реплике.
- Если аудио недоступно:
  - «Аудио этой версии не подготовлено. Текст и сохранённые правки доступны; другая дорожка не подставляется.» (`playback.unavailable`);
  - «Не удалось воспроизвести аудио выбранной версии: файл отсутствует, повреждён или недоступен. Текст и сохранённые правки доступны; другая дорожка не подставляется.» (`playback.failed`);
  - Текст и правки остаются полностью доступны для просмотра и редактирования; приложение не подставляет одиночные дорожки записи или миксы других версий;
  - Повторная обработка из истории кнопкой «Повторить обработку» создаёт новую изолированную версию, не перезаписывая старую на месте.

### 1.4 Назначение имён говорящим (`editnamecalendaronlyhint groupconfirmcounts/replace toggle pertrackwarnings uncappedhuman names`)

- Клик по имени реплики открывает панель назначения имени НАД списком (не инлайн в строке).
- Участники из календаря отображаются в виде подсказок (hints only); автоматического назначения на реплики не происходит.
- Селектор области действия: «Только этой реплике» или «Всему голосу (Микрофон / Системный звук · Голос N)».
- Переключатель «Заменять существующие ручные назначения» (по умолчанию выключен) с динамическим превью затрагиваемых и заменяемых реплик («Затрагивает: X из Y реплик; заменяет ручных: Z»).
- Явное подтверждение для массового назначения группы перед сохранением.
- Предупреждения машинной диаризации Nemotron об ограничении 8 голосов раздельно по дорожкам (`[Микрофон]`, `[Системный звук]`).
- Число назначаемых пользователем человеческих имён не ограничено. Кнопка «Сбросить имя» возвращает дефолтное `Speaker N`. Пустые имена отклоняются с ошибкой валидации.

### 1.5 Редактирование текста, отмена и ошибки (`textsavecancel errorretention undo disabledpendingdraft unsavedclose/versionchoices`)

- Кнопка с карандашом в строке реплики открывает многострочный редактор `TextEditor`.
- Кнопки «Сохранить текст» и «Отмена». Поддерживается сохранение пустого текста `""` (очищает текст реплики; строка, таймкод `[HH:MM:SS]` и имя говорящего остаются видимыми в окне, реплика не скрывается целиком).
- При ошибке сохранения (ввод-вывод или отказ блокировки) текст ошибки выводится в верхней части окна красным цветом (`model.error`), а введённый черновик остаётся в поле ввода (error retention). Повторная попытка для текста или одиночной реплики выполняется существующей кнопкой «Сохранить текст» / «Сохранить»; для группового назначения кнопка «Сохранить» скрыта, блок подтверждения остаётся видимым, и повтор выполняется кнопкой «Подтвердить». При CAS-конфликте повторное нажатие не разрешает несовпадение данных; черновик безопасно сохраняется в открытом редакторе без автоматического сброса (без вымышленной кнопки перезагрузки в UI).
- Сессионная отмена действий (Undo) кнопкой в окне записывает новую ревизию с инкрементом номера. Во время редактирования черновика (ввода текста или имени) Undo заблокировано для исключения порчи данных.
- Защита несохранённых изменений: диалог подтверждения («Сохранить», «Отбросить», «Остаться») при закрытии окна или смене версии с активным черновиком; сбой сохранения останавливает уход.

### 1.6 Экспорт выбранной сохранённой версии (`exportrequest freezesselectedSAVED state dirtyexcluded keepsdraft realSavePanel explicitexistingoverwrite noinsiderecording/aliases cancellationnofiles failuresretryuser`)

- Кнопка «Экспортировать…» доступна только для валидного документа в режиме `.review`.
- Заморозка состояния (Frozen Snapshot): экспорт читает сохранённый документ и правки из независимого репозитория; изменения на диске во время диалога не меняют экспортируемые данные.
- Исключение черновика: при активном черновике выводится информационное предупреждение (`transcript-export-notice`), что экспортируется только сохранённая версия, а черновик исключён. Черновик остаётся в редакторе.
- Системный диалог `NSSavePanel`: `.plainText`, имя по умолчанию `transcript.txt`, папка по умолчанию «Документы», поясняющее сообщение.
- Явное согласие на перезапись: проверка существования файла выполняется после закрытия панели; при наличии файла (включая созданный во время показа диалога) запрашивается модальное подтверждение через `NSAlert`, и только при согласии разрешается перезапись. Если файл отсутствовал при проверке, но появился в результате гонки после неё, атомарный `renamex_np(..., RENAME_EXCL)` отклоняет запись (`destinationExists`) без перезаписи.
- Защита файлов записи: попытка сохранить в каталог записи или на её псевдонимы (симлинки, device/inode) строго отклоняется (`protectedDestination`).
- Отмена диалога: закрытие панели без выбора не создаёт файлов и не выводит ошибок.
- Обработка сбоев: автоповтор при ошибке записи запрещён; выводится понятное сообщение для ручного повтора.

### 1.7 Политика отбора разрешённых полей (`field allowlist`)

- Пользовательский текст реплик, имена говорящих и поля контекста встречи сохраняются дословно (verbatim) без санитизации.
- Служебные метаданные, технические пути файловой системы и идентификаторы (`sources`, `playback.mixPath`, `schemaVersion`, `turnID`, `wordID`, `speakerID`, `resultID`) исключены из экспорта.
- Сырые диагностические сообщения об ошибках (`warning.message`) исключены; выводятся только безопасные формулировки по стабильным кодам предупреждений (`warning.code`) с меткой дорожки.
- Конвейер транскрибации по-прежнему использует Python для распознавания речи и публикации версий (удаление Python не производилось).
