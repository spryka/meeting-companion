# Руководство и протокол приёмочного тестирования на macOS (UAT)

Дата: 2026-11-01. Change: `transcript-editor`.  
Статус: **WAITING_UAT (задачи 5.2 и 5.3b)**.

Настоящий документ содержит детальные сценарии, пошаговые процедуры, точную топологию интерфейса и строгую методику измерений для ручного приёмочного тестирования редактора транскриптов на реальном оборудовании Mac сопровождающего.

> **Правила безопасности, целостности данных и границы тестирования**:
> 1. **Защита пользовательских данных**: Никогда не удалять и не модифицировать оригинальные пользовательские записи и расшифровки в `~/Library/Application Support/MeetingCompanion/` или рабочем каталоге. Тестирование с инъекцией ошибок проводится только на изолированных синтетических копиях.
> 2. **Запрет запуска установленного приложения**: Не запускать установленное приложение из `/Applications/Meeting Companion.app` во время разработки, чтобы исключить конфликты с рабочими TCC-разрешениями macOS и рабочей историей. Тестирование выполняется строго на локально собранном бинарнике приложения текущей ревизии.
> 3. **Автономность (офлайн)**: Тестирование проводится строго в офлайн-режиме (Wi-Fi и Ethernet отключены). Никакие аудиоданные и метаданные не передаются во внешнюю сеть.
> 4. **8-часовой UAT (5.3b)**: Проводится исключительно на реальной записи пользователя. Искусственные файлы-пустышки и вымышленные результаты измерений запрещены. Все строки протокола заполняются сопровождающим по факту выполнения.

## 1. Конфигурация тестового стенда и идентификация сборки

### 1.1 Идентификация сборки (Build & Code Identity)
- **Отзыв неподтверждённой provenance**: прежние digest «203 файла» и SHA бинарника удалены из утверждений этого протокола: в доступных логах нет исходного manifest, алгоритма отбора и связи этих digest с фактической сборкой. Историческая identity не доказана. HEAD сам по себе не идентифицирует dirty/untracked исходники.
- В этой документационной итерации сборка и запуск не выполнялись. Текущие хэши пяти документов и проверенных файлов кода находятся в приватных `section5-sol1-current-sha256.log` и `section5-sol1-inputs.sha256` каталога RUN из `verification-section-5.md`; это **не** manifest сборки и не доказательство происхождения существующего бинарника.
- **Перед будущим UAT** сопровождающий фиксирует `git rev-parse HEAD`, dirty/untracked status и создаёт построчный SHA-256 manifest: только явно перечисленные build inputs (`Package.swift`, `Package.resolved`, `Sources/`, `Resources/`, используемые `scripts/`, `transcription/`, включая untracked исходники; спецификации отдельным списком). Рекурсивно выбрать обычные файлы, исключить credentials/keys, recordings/audio, caches, `.git`, `.build`, `dist` и симлинки наружу; отсортировать относительные пути в `LC_ALL=C`, формат строки `shasum -a 256` — digest и путь. Сохранить полный список, правила исключения, manifest и его `shasum -a 256`; никаких секретов или имён личных записей. Если вход нельзя безопасно включить, отметить пробел provenance, не заявлять полную identity.
- В неизменяемой копии этих inputs выполнить офлайн `swift build -c release --product MeetingCompanionApp --disable-automatic-resolution --skip-update` (только при заранее доступных зависимостях; без установки, сети или signing). Сохранить сырой build log, cwd, команду, exit; `swift build -c release --show-bin-path --disable-automatic-resolution --skip-update` определяет каталог, не предполагать `.build/out` универсальным.
- Сразу после успешной сборки сохранить SHA-256 фактического `MeetingCompanionApp`, повторить manifest inputs и проверить совпадение до/после; перед UAT повторить SHA бинарника. Записать фактический абсолютный путь, PID и команду запуска в приватном протоколе. При несовпадении или отсутствии build log идентификацию повторить, UAT не начинать. Далее `.build/out/Products/Release/MeetingCompanionApp` — только пример пути, подставляется проверенный путь.
- Установленный артефакт `/Applications/Meeting Companion.app` не идентифицирован; не запускать и не завершать его.

### 1.3 Обязательная изоляция ДО любого запуска

Отдельный бинарник не изолирует данные. `AppMain.swift` использует `UserDefaults.standard` (`recordingsDirectory`, настройки, запись уже в `init`), `RecordingPaths.defaultOutputDirectory` — каталог пользователя; `RecorderAppDelegate.swift` обращается к login items и календарю. `RecordingHistory.putThrowing` пишет metadata рядом с записью, выбор версии — `selectedResultID`, редактор — `edits.json`; retry пишет новые артефакты. Поддерживаемого общего env/CLI override профиля для этого UAT не установлено; подмена `HOME` не является проверенной изоляцией.

Сопровождающий вручную подготавливает отдельного локального пользователя macOS без iCloud/рабочего календаря, общих preferences, login items и смонтированных рабочих записей; входить в него до первого запуска. Не менять bundle ID/signing для обхода TCC. **До запуска, редактирования и retry** вручную подготовить отдельную полную копию нужной записи в домашнем каталоге этого пользователя, не symlink/hardlink/alias на оригинал. Для 5.3b это копия реальной восьмичасовой записи, не синтетика. Проверить, что абсолютные `recording`/`log` в скопированной history metadata и внутренние ссылки не ведут к оригиналу; при необходимости адаптировать только копию и сохранить приватную запись изменений. Если безопасный перенос не проверен — STOP.

При первом запуске в отдельном пользователе выбрать тестовый каталог копий штатной настройкой каталога записей; убедиться, что история содержит только копии. Оригиналы не должны быть доступны на запись этому пользователю. Снимки/видео/trace могут содержать личные данные: хранить локально приватно, в отчёт включать только обезличенные значения. Аккаунт, копирование и запуск в текущей итерации **не выполнялись**. Любая невозможность изоляции блокирует UAT, а не разрешает запуск в рабочем профиле.

## 2. Топология интерфейса окна TranscriptReviewWindow

Для исключения ошибок навигации зафиксировано точное фактическое расположение элементов по коду `TranscriptReviewWindow.swift`:
1. **Шапка окна (Header)**:
   - Селектор опубликованных версий (`Picker("Версия:", selection: ...)`).
   - Кнопка отмены последнего действия (`Button("Отменить изменение")` / `transcript-undo`), блокируется при активном черновике.
   - Кнопка экспорта (`Button("Экспортировать…")` / `transcript-export`).
   - Информационные предупреждения и баннеры ошибок (диаризация Nemotron 8+8, экспорт, сбой аудио) — выводятся под тулбаром.
2. **Панель назначения имени спикера (Speaker Assignment Form)**:
   - Расположена **НАД списком реплик** (`name form above list not inline`), открывается при клике на имя спикера в реплике.
   - Содержит: текстовое поле ввода имени, фишки-подсказки из календаря, переключатель области («Только этой реплике» / «Всему голосу»), чекбокс «Заменять существующие ручные назначения» с превью счётчиков, кнопки «Сохранить», «Отмена» и «Сбросить имя».
3. **Список реплик (Turns List)**:
   - `ScrollViewReader` с виртуализированным списком строк.
   - Каждая строка реплики: синяя кнопка таймкода `[HH:MM:SS]`, кнопка имени говорящего (открывает форму назначения над списком), кнопка с карандашом (открывает инлайн-редактор текста прямо в строке).
   - Инлайн-редактор текста: многострочный `TextEditor`, кнопки «Сохранить текст» и «Отмена». Взаимное исключение: пока открыт черновик имени, открытие текстового редактора блокируется.
4. **Кнопка «Вернуться к воспроизведению»**:
   - Расположена **ПОД списком реплик** (`return below list`), появляется только при приостановленном автоскролле (после ручной прокрутки или редактирования).
5. **Панель плеера (Bottom Playback Bar)**:
   - Расположена в самом низу окна: кнопка «Воспроизвести» / «Пауза», текстовые таймкоды `текущее / общее`, ползунок `Slider` для перемотки, текстовый статус аудио (`transcript-audio-status`).
6. **Источник аудиомикса**:
   - Конвейер транскрибации создаёт микс `mix.m4a` (или `mix.wav`), путь к которому берётся строго из поля `playback.mixPath` выбранной версии `result.json`.

## 3. Процедура функционального приёмочного тестирования 5.2

Все шаги выполняются на реальном Mac сопровождающего с запуском бинарника `.build/out/Products/Release/MeetingCompanionApp`. Результаты заносятся в итоговую таблицу раздела 5.

### 3.1 Точка входа из истории и канонический фокус окна
- **Предусловие**: В истории записей присутствует запись со структурированным результатом распознавания.
- **Шаг 1**: В окне истории нажмите кнопку **«Открыть расшифровку»**.
  - *Ожидается*: Открывается отдельное окно `TranscriptReviewWindow` для данной записи.
- **Шаг 2**: Не закрывая окно расшифровки, перейдите в окно истории и снова нажмите «Открыть расшифровку» для этой же записи.
  - *Ожидается*: Второе окно не создаётся; существующее окно активируется и выводится на передний план.

### 3.2 Режим старого формата TXT (Legacy Read-Only)
- **Предусловие**: В изолированной истории выбрана копия исторической записи с `<basename>.sources.transcript.txt` без опубликованного `result.json` (`RecordingEntry.transcript`); это не экспортный `transcript.txt`.
- **Шаг 1**: Нажмите «Открыть расшифровку».
  - *Ожидается*: Окно открывается в безопасном режиме «Только чтение» (`legacyReadOnly`):
    - Отображается полный текст записи;
    - Селектор версий отсутствует;
    - Кнопки плеера («Воспроизвести», ползунок) отсутствуют или заблокированы;
    - Иконки карандаша и кнопки редактирования отсутствуют;
    - Кнопка экспорта заблокирована (`canExport == false`).

### 3.3 Визуальные темы оформления (Light и Dark Theme)
- **Шаг 1**: Переключите macOS в **Светлую тему** (Light Mode).
  - *Ожидается*: Фон окна светлый, контрастный текст реплик, чёткие границы полей ввода, различимая подсветка активной строки при воспроизведении.
- **Шаг 2**: Переключите macOS в **Тёмную тему** (Dark Mode).
  - *Ожидается*: Тёмный фон, контрастный светлый текст, подсветка активных реплик не вызывает зрительного дискомфорта, кнопки и таймкоды различимы.

### 3.4 Доступность и VoiceOver (`Cmd + F5`)
- **Шаг 1**: Включите VoiceOver (`Cmd + F5`).
- **Шаг 2**: Используя клавиши навигации VoiceOver (`VO + стрелки`), обойдите основные элементы:
  - Проверьте озвучивание селектора версий;
  - Проверьте озвучивание кнопки Play/Pause и слайдера перемотки;
  - Проверьте озвучивание строк реплик: таймкод, имя спикера, текст;
  - Проверьте озвучивание баннеров ошибок при их наличии.
- **Шаг 3**: Выключите VoiceOver (`Cmd + F5`).

### 3.5 Воспроизведение звука, синхронизация и проверка AEC
- **Шаг 1**: Нажмите кнопку «Воспроизвести» (`transcript-play-pause`). Глобального shortcut Space в коде нет; клавиатурную активацию проверять отдельно после фактического фокуса кнопки, не из поля редактирования.
  - *Ожидается*: Звук воспроизводится чисто, без щелчков и артефактов; ползунок времени движется синхронно.
- **Шаг 2 (AEC On)**: Прослушайте версию с успешно применённым эхоподавлением:
  - *Ожидается*: В миксе звучит микрофон с подавленным эхом удалённых участников и системный звук.
- **Шаг 3 (AEC Off / Bypassed)**: Прослушайте версию, где AEC был отключён или обойдён:
  - *Ожидается*: Звучит исходный микрофон без артефактов фильтрации.
- **Шаг 4 (Перекрытия)**: Найдите фрагмент одновременной речи в записи:
  - *Ожидается*: Обе реплики слышны одновременно, в окне одновременно подсвечиваются обе звучащие строки в порядке отображения.
- **Шаг 5 (Переход по таймкоду)**: Нажмите синюю кнопку таймкода `[HH:MM:SS]` на реплике в середине списка:
  - *Ожидается*: Воспроизведение мгновенно переходит на начало реплики, подсветка обновляется.

### 3.6 Автоскролл (Follow Mode) и ручная прокрутка
- **Шаг 1**: При воспроизведении убедитесь, что список автоматически прокручивается, удерживая звучащую реплику в поле видимости.
- **Шаг 2**: Прокрутите список трекпадом или колёсиком мыши к другому месту записи:
  - *Ожидается*: Автоскролл немедленно приостанавливается; звук продолжается; под списком реплик появляется кнопка **«Вернуться к воспроизведению»**.
- **Шаг 3**: Нажмите «Вернуться к воспроизведению»:
  - *Ожидается*: Список плавно возвращается к звучащей реплике, автоскролл возобновляется.

### 3.7 Редактирование текста И имени говорящего, сохранение, ЗАКРЫТИЕ ПРИЛОЖЕНИЯ И REOPEN
- **Шаг 1 (Назначение имени — обязательное сохранение перед текстом)**:
  - Кликните по имени `Speaker 1` на строке реплики.
  - Над списком реплик открывается панель назначения имени.
  - Введите имя «Борис», выберите область «Только этой реплике».
  - **ВАЖНО**: Нажмите кнопку **«Сохранить»** над списком, чтобы зафиксировать и закрыть черновик имени (правило взаимного исключения блокирует открытие редактора текста при открытой панели имени).
  - *Ожидается*: Черновик имени закрыт, строка обновилась на «Борис».
- **Шаг 2 (Редактирование текста)**:
  - Только после сохранения имени нажмите иконку карандаша на этой же реплике.
  - В строке открывается инлайн `TextEditor`. Отредактируйте текст реплики и нажмите «Сохранить текст».
  - *Ожидается*: Текст реплики обновлён в строке; на диске записан `edits.json`.
- **Шаг 3 (Сессионный Undo)**:
  - Нажмите «Отменить изменение» в тулбаре -> последнее сохранение текста отменяется.
  - Повторно отредактируйте и сохраните окончательный текст.
- **Шаг 4 (Закрытие окна и ИЗОЛИРОВАННЫЙ РЕСТАРТ ПРИЛОЖЕНИЯ)**:
  - Закройте окно расшифровки (`Cmd + W`).
  - Завершите процесс тестового приложения (`Cmd + Q` для процесса `.build/out/Products/Release/MeetingCompanionApp`).
  - Убедитесь через `ps -o pid,comm -p <PID>`, что процесс завершён (без завершения установленного приложения `/Applications/Meeting Companion.app`).
- **Шаг 5 (НАСТОЯЩИЙ REOPEN ИЗ ИСТОРИИ ПОСЛЕ РЕСТАРТА)**:
  - Запустите тестовый бинарник приложения заново.
  - В окне истории нажмите «Открыть расшифровку» для этой записи.
  - *Ожидается (проверка требования Durable edits / Reopen edited result)*:
    - Открывается окно из сохранённого состояния на диске;
    - Назначенное имя «Борис» полностью сохранено;
    - Отредактированный текст реплики полностью сохранён;
    - Исходный GigaAM baseline в файле `result.json` не затронут.

### 3.8 Явный выбор микса старой версии и изоляция retry
- **Шаг 1**: В записи с несколькими версиями переключите версию в селекторе версий на более раннюю (`v1`).
  - *Ожидается*: Плеер загружает и воспроизводит микс именно этой выбранной версии (`raw/transcripts/v1/mix.m4a`), а не последней версии.
- **Шаг 2 (Изоляция при фоновом retry)**:
   - Выполните повторную обработку только копии записи из изолированной истории, при заранее подготовленном офлайн runtime; если требуется установка/сеть — STOP. Не инжектировать результат вместо проверки настоящего retry.
   - *Ожидается*: Текущее окно остаётся на `v1` (`pinned`), её микс и правки неизменны. `versions` загружается только в `TranscriptReviewWindowModel.init` (строка 509), автоматического обновления текущего селектора нет.
   - После успешной публикации сохраните/отмените черновики, закройте именно окно расшифровки и заново откройте его из истории: новая модель перечитает версии. Выбор после reopen определяется сохранённым `selectedResultID`; retry может обновить его в истории, поэтому не обещается автоматическое открытие `v1`. Явно выберите `v1`, проверьте старые правки/микс, затем явно выберите новую версию; отсутствие переноса правок проверьте отдельно. Повторный клик в истории без закрытия лишь фокусирует старое окно и не обновляет список.

### 3.9 Экспорт в TXT и защита от перезаписи (NSSavePanel)
- **Шаг 1**: Нажмите кнопку «Экспортировать…».
  - *Ожидается*: Если открыт несохранённый черновик, выводится предупреждение о его исключении.
  - Открывается лист `NSSavePanel` с именем `transcript.txt` в папке «Документы».
- **Шаг 2 (Отмена)**: Нажмите «Отмена» -> файл не создаётся, ошибок нет.
- **Шаг 3 (Согласие на перезапись)**: Выберите имя существующего файла в Документах:
  - Появляется системный модальный `NSAlert` с подтверждением перезаписи.
  - При отказе («Отмена») исходный файл не изменяется.

## 4. Процедура 8-часового UAT на стабильность и производительность (Task 5.3b)

### 4.1 Методология измерений и правила

1. **Исключение времени транскрибации**: Запись длительностью 8 часов должна быть полностью распознана заранее. Время работы ML-моделей GigaAM/Nemotron **не входит** в замеры UI.
2. **Замер задержки управления (Control Response <= 200 мс)**:
   - Ручной секундомер строго **не используется** (физиологическая реакция человека ~150–250 мс не позволяет замерить порог 200 мс).
   - Используется **синхронизированная видеозапись экрана с частотой 60 или 120 кадров/с (fps)** (QuickTime Screen Recording с системной индикацией кликов мыши / нажатия клавиш Accessibility или программный маркер ввода).
   - Задержка реакции определяется по счётчику видеокадров $\Delta N$ от маркера ввода (frame event boundary нажатия кнопки мыши или клавиши) до первого кадра изменения визуального состояния UI (frame visual response boundary).
    - Зафиксировать measured FPS, пропуски кадров, задержку маркера и A/V sync. При подтверждённой синхронизации и отсутствии пропусков кадров границы: $L=\max(0,(\Delta N-1)\tau)$, $U=(\Delta N+1)\tau$, где $\tau=1/\text{measured\_FPS}$. Иные погрешности маркера/sync дополнительно расширяют интервал; если их нельзя ограничить, результат INCONCLUSIVE.
    - Выполняется серия из не менее 5 замеров для различных действий (клик кнопки плеера, открытие формы имени, переключение версии) с вычислением среднего и максимума.
    - **Правило для всех временных порогов** (отклик 200 мс, seek 1 с, cold/reopen 5 с): PASS только если верхняя граница $U$ каждого замера с учётом всех погрешностей <= порога; FAIL если нижняя граница $L$ > порога; пересечение порога — INCONCLUSIVE, повторить с лучшей точностью. Среднее не компенсирует превышение максимума. Например, 12 кадров при 60 fps — не PASS для 200 мс: $U\approx216.7$ мс. Для audible onset включить неопределённость аудиомаркера и A/V sync, сохранить исходные кадры/волну и расчёт L/U.
3. **Замер задержки перемотки (Seek Latency <= 1.0 с)**:
   - **Обязательное предусловие**: Воспроизведение должно быть активно запущено (**режим playing**), чтобы аудиотранспорт находился в состоянии потокового чтения.
   - Замеряется интервал от момента клика по таймкоду или отпускания слайдера до **слышимого старта звука новой позиции (audible onset)**, фиксируемого по синхронной аудиозаписи / волновой форме в аудиоредакторе (QuickTime / Audacity), а не только по визуальному смещению ползунка.
4. **Замер памяти и разграничение доказательств потокового воспроизведения (Streaming)**:
   - **Выборочный максимум RSS (Sampled Max RSS)**: мониторинг процесса приложения с частотой 1 Гц (`while true; do ps -o pid,%cpu,rss -p <PID>; sleep 1; done >> memory_profile.csv`). Частота 1 Гц даёт выборочный максимум, но может пропускать кратковременные пики (transient allocation spikes).
   - **Ограничение RSS-метрики**: 8 часов несжатого аудио (16 кГц, 16-бит моно PCM) составляют **~879 MiB**. Поскольку $879\text{ MiB} < 1024\text{ MiB}$ (порог 1 GiB), удержание прироста RSS в пределах 1 GiB **само по себе математически не исключает** предзагрузку несжатого PCM в память!
    - Обязательная проверка порога памяти: запускать **один новый тестовый процесс** под `/usr/bin/time -l <проверенный-бинарник>` и сохранять stderr приватно. До открытия зафиксировать baseline RSS через `ps` (KiB, умножить на 1024). После всего сценария штатно завершить только этот процесс и взять kernel lifetime `maximum resident set size` (macOS: bytes) из `time -l`. Точная консервативная метрика: `G = max(0, lifetime_max_RSS_bytes - baseline_RSS_bytes)`. Lifetime peak включает запуск до baseline и потому не занижает максимум после открытия. PASS памяти только при `G <= 1073741824 bytes` (1 GiB); sampled max не используется для PASS. Сохранить PID, baseline, время начала/конца, сырой time output, единицы и расчёт. Если kernel maximum недоступен/единицы не подтверждены или процесс заменился — INCONCLUSIVE. Превышение консервативного G до baseline требует отдельного ограниченного профиля для локализации, не заявления PASS.
    - Отдельное доказательство отсутствия полной предзагрузки состоит из двух обязательных частей, ни одна не заменяет другую или порог памяти:
     1. **Статический архитектурный анализ кода**: `TranscriptAVPlayerTransport.swift` использует нативный streaming-пайплайн `AVURLAsset` / `AVPlayer` по file URL без буферизации `Data(contentsOf:)`.
      2. **Обязательный Instruments trace (Allocations + VM Tracker + File Activity)**: начать до открытия, не исключать кратковременные/освобождённые allocations, записывать весь сеанс, включая первое play, seek в начало/середину/конец, close/reopen. Сохранить настройки, временные границы, allocation backtraces, VM regions и file offsets чтения/отображения выбранного микса. Проверить live и transient allocations, cumulative allocations отличать от одновременно resident. Для PASS streaming должно быть видно чтение/декодирование по мере playback/seek и ограниченное рабочее множество, без resident decoded buffer всего аудио (~879 MiB для 8ч PCM16/16kHz mono), без resident копии всего сжатого микса и без decode-all-and-discard до первого play. Один лишь mmap целого файла не означает resident preload: нужны page residency и активность чтения. Любой пробел trace, неразрешимые attribution/region или отсутствие видимости декодера — INCONCLUSIVE; полная предзагрузка — FAIL. Не задаётся вымышленный порог «единицы мегабайт» и не заявляется результат без трассы. Instruments sampling не доказывает kernel maximum RSS: для порога используется G выше.
