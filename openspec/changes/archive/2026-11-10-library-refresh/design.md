# UI и поведение

## Context

Baseline: master `19c84249e8141442601eab88b7846a0b9592f6f7` (merge trash-recording). Предыдущие изменения уже в архиве. Сейчас refresh вызывается при запуске, смене outputDirectory и первом входе в history, если initial load ещё не завершён. Ручной команды и ⌘R нет.

Repository уже сканирует вложенные каталоги, объединяет записи по canonical identity и защищает более свежие revisions, working/unsaved entries и trash reservations. Это merge, а не удаление всех отсутствующих на диске строк.

## Goals / Non-Goals

Цель: убрать дубль создания записи и дать явное чтение текущей библиотеки, включая возвращённую из Корзины папку.

Вне scope: watcher, refresh при активации окна, импорт из произвольной папки, очистка отсутствующих строк, миграция, новые форматы, управление Корзиной, floating action button, переработка плеера или капсулы.

## Decisions

### 1. Точная компоновка

| Область | Вид и действие |
|---|---|
| Заголовок списка, все ширины | «Записи», справа существующий счётчик и вместо «+» круговая стрелка обновления. Счётчик сохраняет прежний смысл — количество видимых записей |
| Обычная кнопка обновления | Существующий нейтральный icon-button: область 36×36 pt, иконка 16 pt, прежние фон/радиус/hover. Native symbol `arrow.clockwise` либо уже существующий эквивалент той же формы |
| Wide/compact >767 pt | Основная синяя «Новая запись» остаётся на прежнем месте справа в toolbar. В списке второй кнопки создания нет |
| Narrow list <=767 pt | Под строкой «Записи» и перед поиском — синяя «Новая запись» с существующим символом «+», на ширину доступного списка, высота не менее 44 pt. Отступы по краям 16 pt, между элементами 16 pt. Refresh сохраняется в заголовке, hit area не менее 44×44 pt |
| Narrow detail <=767 pt | Локальная кнопка списка скрыта вместе со списком; действие создания в toolbar документа остаётся. «Все записи»/back работает как прежде |

Порог берётся из существующей компоновки окна, не из типа устройства. При resize не показывать одновременно две «Новые записи» и не оставлять фокус на скрытом контроле. Ширина sidebar, бренд, системные traffic lights, divider, поиск, карточки и player не меняются.

Tooltip refresh: «Обновить библиотеку (⌘R)». Accessibility label: «Обновить библиотеку». Пункт нативного меню «Вид → Обновить библиотеку», shortcut ⌘R. Не добавлять этот пункт в меню действий выбранной записи «…». ⌘N и все видимые кнопки создания используют прежнюю guarded команду открытия формы, без автоматического старта capture.

Почему: обновление относится ко всему списку; создание остаётся основным действием. Floating-кнопка добавила бы новую позицию и перекрывала контент. Постоянная вторая «Новая запись» сохраняла бы исходный дубль.

### 2. Одна команда и сохранение состояния

Pointer, нативное меню и ⌘R вызывают один guarded request на текущий outputDirectory. Проверки — в общей команде, не только в disabled кнопки. Native shortcut маршрутизируется через существующий WorkspaceWindow; без global event monitor.

Допуск: приложение активно, workspace видим и является keyboard target для shortcut/menu, открыта библиотека/history (список или документ), нет draft/modal/Settings/native sheet/trash admission или выполняющегося удаления. Во время initial scan или refresh новый запрос не стартует и не откладывается. Фокус в обычном поле поиска не запрещает явный ⌘R; native меню/редактор и modal сохраняют свой приоритет. Скрытая/свёрнутая библиотека, форма записи и capsule не становятся целями ⌘R.

Запись/очередь обработки сами по себе не запрещают обновление открытой библиотеки. Сканирование идёт вне MainActor через прежний repository; новые данные не перетирают working entries, unsaved metadata или updates, произошедшие после старта scan. Сохранить generation/revision/trash guards. Зафиксировать root и request identity до await: поздний ответ не публикует устаревший root или чужие loading/error состояния. Смена root во время старого scan допускает штатную загрузку нового root, а не теряется из-за ручного busy-флага.

Применять snapshot по существующей canonical URL identity, не по строковому заголовку или позиции. Сохранять query, выбранный URL, focus, видимую область списка с её смещением, тот же editor/session, прокрутку текста и playback position/play state. Не вызывать повторное открытие выбранного документа лишь из-за изменения массива history. Если прежняя видимая строка исчезла по независимому штатному событию, использовать ближайшую сохранившуюся строку без перехода к началу. Refresh не выбирает новую запись и не запускает ASR/retry. Изменённый извне current разрешается при следующем явном открытии, а не подменяет текущую session посреди чтения.

### 3. Восстановленная папка

Пользователь возвращает целую папку записи из системной Корзины на прежнее место внутри текущего library root, затем нажимает refresh или ⌘R. Штатный scanner заново находит запись, merge добавляет ровно одну строку; сортировка по дате, displayTitle и поиск используют прежние правила. Сохранённые recognition/edits/audio читаются существующими средствами. Если query скрывает запись, он сохраняется: пользователь очищает поиск, чтобы увидеть её.

Нет постоянного tombstone, который запрещает повторное обнаружение действительно возвращённой папки. При этом scan, начатый до удаления, не может воскресить уже удалённую запись. Не менять правила поддержки layout: возвращение в другое место вне root не является импортом, flat legacy остаётся read-only. Не обещать очистку строк после внешнего удаления файлов — текущий merge это не делает.

### 4. Состояния без скачков

| Состояние | Отображение |
|---|---|
| Idle | Круговая стрелка доступна при выполнении guards |
| Обновление | В той же области кнопки — небольшой indeterminate progress indicator; кнопка и команда меню disabled. Под поиском строка «Обновляем библиотеку…», accessibility value сообщает занятость. Старый список остаётся видимым и доступным, кроме уже действующих modal-блокировок |
| Успех | Индикатор и строка ожидания исчезают, кнопка возвращается; VoiceOver получает «Библиотека обновлена». Без toast, alert, автоматического выбора и переноса фокуса |
| Ошибка/частичное чтение | В том же месте под поиском вместо ожидания — «Не удалось полностью обновить библиотеку. Повторите обновление» и безопасная причина. Цвет warning плюс текст; прочитанные и прежние записи остаются. Команда снова доступна |
| Нет записей | Штатное empty state только после завершённого чтения без ошибки; ошибка доступа не выдаётся за пустую библиотеку |

Refresh error принадлежит своему запросу, очищается после его успешного повтора; не стирать чужие ошибки сохранения/обработки. Проверить отсутствие root и отказ enumerator: нынешний scanner может вернуть пустой успех, это нельзя показывать как подтверждённое успешное ручное обновление. Добавить только необходимое различение результата, сохранив поведение остальных сценариев.

## Risks / Trade-offs

- Race с удалением/обработкой → переиспользовать общий repository и его reservations/revisions; проверить настоящие interleavings синтетическими fixtures.
- SwiftUI rebuild сбрасывает review или scroll → стабильная identity и отсутствие команды reopen; отдельная проверка native UI.
- Кнопка в HTML может перехватывать browser reload → HTML не является реализацией macOS shortcut; приёмка на native workspace.

## Migration Plan

Формат данных и настройки не меняются. Добавить команду/UI поверх текущих services; rollback — revert кода этого change без преобразования пользовательских файлов. Старые архивные changes не переписывать.

## Open Questions

Продуктовых вопросов нет. Конкретный механизм scroll restoration и off-main dispatch выбрать в рамках существующих компонентов. Если implementation требует нового хранилища или изменения ownership, остановиться и отдельно согласовать расширение.
