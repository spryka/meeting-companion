## Context

L02 закрепляет merge без удаления отсутствующих строк. После переноса файлов
внешней командой приложение хранит прежний `entriesMap`, и ⌘R не исправляет счётчик.
Меняется только capability library-refresh; остальные локальные изменения
в рабочем дереве сохраняются. Все семь корневых ADR прочитаны.

## Goals / Non-Goals

**Goals:** полная сверка списка при успешном scan, сохранение ошибок, работы,
конкурентных изменений и существующего документа оставшейся записи.

**Non-Goals:** watcher, новые кнопки/настройки/форматы, миграция или удаление файлов,
изменения транскрибации, автоматическая установка/публикация.

## Decisions

1. В существующей транзакции `RecordingHistoryRepository.refresh` сравнивать
   canonical identities выдачи и entries текущего canonical root. Убирать
   отсутствующие только при полном scan без ошибки, совпадении revision запроса
   и отсутствии working/unsaved/work/trash protection. Запрос запоминает
   также исходный набор identities: впервые загруженная во время scan запись
   защищена даже до появления отдельной revision. Отдельная проверка
   файлов для каждого отсутствующего entry не заменяет полноту scan: standard
   папка может оставаться полноценной записью без корневого mixed M4A.
   Альтернатива полной замены map теряет текущую работу и concurrent mutations.
2. При удалении строки увеличивать её revision и сохранять revision tombstone:
   snapshot остаётся монотонным, поздние callback не воскрешают исчезнувшую папку,
   восстановление по прежнему пути остаётся доступно. Успешная пустая выдача
   отличается от ошибки/недоступного root. Entries вне root сохраняются.
3. После guarded manual refresh при прежнем root и исчезнувшей текущей selection
   переиспользовать `workspace.closeCurrent`, сбросить selection, инвалидировать
   старый load generation. После scan и до merge запрашивать на MainActor
   identities, защищённые текущим вводом: выбранная строка сохраняется вместе
   с presenting view модального редактора. Callback передаёт только Set<URL>
   вне repository lock, Application не зависит от UI. Повторно проверять input
   перед закрытием; появившийся во время scan ввод не закрывать.
   Сохранившуюся выбранную запись не переоткрывать.

## Risks / Trade-offs

- Неполный scan выглядит как удаление → prune только при отсутствии scan error;
  регрессии для partial/nil enumeration и missing root.
- Очередь захватила запись до смены phase → проверять work reservations,
  включая пересечение содержащих папок; существующие trash guards сохраняются.
- Изменение после beginRefresh → текущая revision имеет приоритет; stale generation
  не публикуется. Новая запись с новым revision не удаляется старой выдачей.
- Новый ввод во время scan → не закрывать session, повторно разрешать очистку
  только явным следующим refresh после разрешения ввода.

## Migration Plan

Формат и файлы не меняются. TDD на синтетических папках для standard/flat,
пустого/ошибочного scan, work/unsaved/concurrent protection и восстановления.
App tests проверяют счётчик через entries, selection, закрытие player/session
и сохранение другой выбранной записи. Затем strict OpenSpec validation, release
build, Swift tests и обязательные repository checks. Установка отдельно.
