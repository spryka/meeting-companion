# Дизайн и реализация

## Context / Goals

Продолжить текущий native UI библиотеки. Удаляется одна ненужная встреча с диска и из списка через системную Корзину. Только отдельные standard-папки. Без soft-hide, batch delete, permanent delete, собственного undo/восстановления или переработки хранения.

## UI

**Строка библиотеки.** Справа отдельная кнопка с SF Symbol `trash`, размер glyph 16 pt, hit area 28×28 pt, отступ от правого края 8 pt. Зарезервировать её ширину: появление не двигает заголовок. В обычном состоянии нейтральный ODColors.muted, при hover/keyboard focus destructive accent из существующего ODColors.red. Видна только у выбранной записи: выбор кликом или стрелками открывает её существующий transcript route. Hover или Tab-фокус невыбранной строки не показывают и не активируют корзинку. Tooltip «В Корзину…», accessibility label «Переместить запись <название> в Корзину». Не вкладывать Button в Button: область выбора и корзина соседние hit targets.

Контекстного меню у строки библиотеки нет. В существующее toolbar More «…» добавить «В Корзину…» с тем же `trash`, внизу после разделителя под «Настройки»; команда относится к выбранной записи. Все входы передают стабильную recording identity одному guarded command и открывают то же подтверждение. Busy-кнопка и пункт меню disabled, пояснение «Дождитесь завершения работы с записью». Flat/shared: «Доступно только для записи в отдельной папке». Не ограничиваться tooltip: причина доступна accessibility и в feedback программной команды.

**Подтверждение.** Одно модальное подтверждение, привязанное к workspace, без самостоятельного окна. Пока оно открыто, библиотека заблокирована для pointer, keyboard, toolbar и программных navigation/rename/retry/trash/Settings-команд. Красная кнопка окна, ⌘W и команды закрытия/скрытия workspace отклоняются: сначала требуется «Отмена» или «В Корзину». Клик по фону не закрывает подтверждение. Escape равнозначен «Отмена». Независимо висящей модалки после закрытия родительского окна быть не должно; повторная команда не создаёт второй экземпляр. Блокировка ввода не останавливает фоновую запись/обработку других встреч. Точный заголовок: `Переместить запись «<название>» в Корзину?` Полное имя переносится, не обрезается. Текст: `Вся папка встречи, включая аудио, транскрипт и остальные файлы, будет перемещена в Корзину macOS. Восстановить её можно через Finder.` Показать реальный путь папки под пояснением, доступный целиком. Кнопки: «Отмена» слева, «В Корзину» справа с destructive role. По явному уточнению владельца Return/Enter подтверждают, Escape отменяет; default action — «В Корзину» (или разрешённый «Повторить» при известной ошибке). Отмена сохраняет selection/focus/scroll.

**Клавиатурная чистка.** Backspace/Delete без модификаторов в активной видимой библиотеке или на контроле её выбранной строки открывают то же подтверждение для выбранной identity. В search/editor/native input, под Settings/sheet и вне активного workspace команды не перехватываются; auto-repeat удаления игнорируется. Перед отложенным исполнением повторно проверить окно, focus и выбранную запись. Return/Enter действует только на тот же открытый dialog id, с повторной проверкой active/modal/pending guards; при pending и неизвестном результате повтор не выполняется. После удаления прежний контракт сохраняется: selection пуст, фокус у соседней строки без автоматического открытия. Первая ↑/↓ или Space открывает именно сфокусированную соседнюю строку и возвращает focus библиотеке, затем можно продолжить Backspace/Delete → Enter. При пустой selection стрелка не пропускает соседа и работает даже для единственной оставшейся строки; если selection уже есть, действует прежняя навигация библиотеки. Identity берётся у сфокусированной строки, не из прежнего сохранённого индекса.

**Выполнение.** До выбора «В Корзину» файловых изменений нет. После подтверждения модальность и запрет закрытия родителя сохраняются до результата операции; отмена уже начатого перемещения не предлагается. Выполняется одна операция; кнопки подтверждения/повторный trash недоступны, подпись `Перемещаем в Корзину…`. Не скрывать строку заранее. После успеха закрыть sheet, обновить список, краткий feedback `Запись перемещена в Корзину`. Свой Undo не добавлять. Если удалена выбранная запись, справа пустое состояние `Выбери запись` / `Выбери встречу в библиотеке`; автоматически другую не открывать. Если видимых записей больше нет, показать «Записей пока нет» или существующий no-matches при активном поиске. Если удалена другая запись, текущий transcript/player/scroll не менять. Фокус после успеха — соседняя доступная строка без её открытия, иначе поиск. Счётчик/группы дней пересчитываются.

Ошибка: оставить строку, показать `Не удалось переместить запись в Корзину` и системную причину в том же модальном подтверждении; «Отмена» возвращает в библиотеку без нового перемещения, явный «Повторить» доступен только при известном неуспехе. При ошибке библиотека остаётся заблокированной до решения пользователя. Неопределённый исход сначала согласуется с диском, без повторного trash; если источник уже отсутствует, перечитать историю без заявления о нашем успешном перемещении. Закрытая перед операцией review-session при ошибке открывается заново по обычному guarded пути, не остаётся stale writer. Если сохранение/закрытие session не удалось, trash не вызывать.

## Техническая граница

Использовать shared Application history/services и существующие ownership/containment/modal/CAS guards; native adapter использует `FileManager.trashItem(at:resultingItemURL:)`. Не вызывать `removeItem` как запасной путь. Прежде чем перемещать: проверить standard layout, canonical containment в принадлежащей записи области, реальный тип directory и отсутствие подмены symlink; имя из UI не используется как путь. Внутренние ссылки не разыменовывать для рекурсивного удаления внешних данных. Корень библиотеки/дата/папка с другой записью запрещены. При неоднозначной принадлежности отказ, не эвристическое удаление.

Точная identity существующей папки фиксируется при подтверждении и перепроверяется после всех await, непосредственно перед перемещением. Захват/очередь/retry/rename и trash используют согласованную reservation/transaction boundary на эту запись: проверка одного `phase.isWorking` недостаточна. Пока reservation удерживается, не допускаются enqueue, запись metadata/edits и второй trash. Освободить её на любом результате. Дисковый вызов не блокирует MainActor; pending admission уже учитывается как занятость.

В master `RecordingHistoryRepository.cancelShortRecording` уже применяет system Trash, но имеет отдельный контракт duration <10s/recording. Не расширять этот метод до удаления произвольных встреч и не менять отмену короткой записи. Переиспользовать подход/общие guards. Repository содержит `reserveWork` и revision/generation защиты: успешное удаление должно инвалидировать старый scan/cache/subscribers и не позволять late update воссоздать папку. Не вводить вторую history database или вечный blacklist: восстановленная пользователем папка при новом scan вновь обнаруживается обычным правилом; автоматическое восстановление пути приложением не реализуется.

## Parallel / Migration / Risks

Это независимый change. Во втором worktree может выполняться `processing-progress-ui`; общие AppMain/RecordingHistoryView/ProcessingService и тесты требуют согласования. Не копировать чужие незакоммиченные файлы и не смешивать модели состояний. Удаление не зависит от нового вида прогресса; оно зависит от реальной занятости Application service.

Данные не мигрируются. В Корзину уходит ВСЁ внутри подтверждённой папки, включая добавленные пользователем файлы; это явно сказано в подтверждении. Внешние экспорты/событие календаря не затрагиваются. Если системная Корзина недоступна, операция завершается ошибкой. Новый root ADR не нужен; пользователь разрешил подготовку функции, а не удаление существующих записей в этой сессии.
