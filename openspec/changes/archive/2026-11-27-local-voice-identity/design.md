job framework. Нужны минимальные типизированные дополнения, без новой очереди
и без ложных ASR history/progress событий от voice job.

## Goals / Non-Goals

**Goals:** локально запоминать знакомые голоса по обычной ручной разметке,
уточнять ограниченный профиль, сохранять уверенные автоимена и оставлять неоднозначные реплики без имени, сохранять базу
независимо от записей и исправлять ошибочный вклад без выбора аудиообразцов.

**Non-Goals:** обучение весов
сети, синхронизация базы, облачное аудио, новый runtime/СУБД, ручной менеджер
эталонов, автосклейка людей по имени, объединение меток Nemotron, отдельное окно
настроек. [Визуальная приёмка](ui-prompt.md) использует эталон в reference/.

## Decisions

### 1. Пользовательский путь и свежий UI

Шестой раздел «Голоса» использует существующую Settings-модалку и admission.
Настройка «Запоминать голоса» по умолчанию выключена. Включение разрешает
ручное обучение. Извлечение признаков требует подготовленной локальной модели,
которую можно подготовить явно. Автоимена требуют дополнительно включённой после
калибровки `VoiceMatchPolicy`. Пока её нет, статус в «Голосах» сообщает, что
автоимена ожидают калибровки. Сохранение введённого имени
использует единственный совпадающий профиль или создаёт нового человека.
Если есть несколько совпадений, выбор личности остаётся за пользователем.
Сохранённое ручное или старое имя без профиля можно подтвердить рядом с
выбранной репликой. Это обычное ручное назначение с узкой областью single:
видимое имя сохраняется, выбранный профиль и событие записываются в edits.
Для этого пути действуют те же проверки качества, повторов и отзыва.
[ADR-0009](../../../../adr/0009-enrol-voices-through-name-edits.md) закрепляет
обучение при ручном назначении. Предложение [ADR-0010](../../../../adr/0010-confirm-existing-speaker-name.md)
уточняет подтверждение старого имени на реплике.
Список и карточка человека доступны с корректным последовательным переходом
в узком workspace. Персональный сброс удаляет эталоны, агрегат и соответствия,
инвалидирует поколения и сохраняет personID и уже опубликованные имена.

Оба входа открывают одну панель «Имена участников» с одним writer и session.
Вход из реплики выбирает её с начальной областью single, из шапки восстанавливает
выбор текущего результата с начальной областью group. Черновики принадлежат
session/resultID/turnID. «Все / Неопознанные» показывает счётчики сохранённых
назначений; смена фильтра или сохранение, исключившее активную группу, выбирает
первую видимую группу с соответствующим фокусом либо показывает пустое состояние.
Смена реплики, «Следующий голос» и возврат к транскрипту сохраняют черновики
в сессии. Конфликтующие смена записи, retry и закрытие требуют разрешения всех
нерешённых черновиков по действующему admission. «Отменить правку» сбрасывает
текущий черновик и возвращает фокус в поле даже при невалидном имени. Escape
сначала обслуживает активное меню/IME, затем отменяет текущий черновик и возвращает
к выбранной реплике.

Выбор имени в «Именах участников» реализован как единый кликабельный комбобокс с живым поиском по дедуплицированным участникам встречи (из календаря и ручных имён записи, с привязкой к единственному сохранённому профилю при совпадении имени) и оставшимся профилям базы, отмечая сохранённые профили иконкой голоса без hex-суффиксов UUID. Одноимённые профили (`personID`) не склеиваются и остаются отдельными выбираемыми пунктами с человекочитаемой подписью/контактом.
Календарный бонус требует однозначно подтверждённой связи с сохранённым
attendee. Равенства строк недостаточно для объединения людей. Группы разделены
по source/voice; mixed-группа показывает «Разные имена». В транскрипте
соседние повторения имени можно свернуть при совпадении personID, источника
и происхождения, сохраняя доступное действие для каждой реплики.

Одна операция сохранения реализует single/remaining/group с актуальным
service-issued preview, сравнением personID и имени, защитой ручных назначений
в массовых областях и CAS. Пользователь может явно выбрать замену ручного
имени. Распространение автоимени хранит derived происхождение и не обучает.
Учится только независимый ручной выбор/исправление. Text-only save сохраняет
personID и origin. Ошибка сохраняет ввод и предыдущее состояние. Статусы имени
и обучения разделены. Интервальное воспроизведение использует общий плеер.

Автоназначение ставится ровно для нового результата из Application после
успешной публикации ASR при включённом запоминании, подготовленной модели и
откалиброванной политике сопоставления. Это отдельный
атомарный edits commit с CAS, защитой ручных имён и устойчивой проверкой нового
resultID. Транскрипт доступен при недоступном голосовом задании. Открытие старой
или новой записи читает сохранённые назначения и не ставит задание. Copy/Export
используют сохранённые edits v1/v2; исходные артефакты ASR не переписываются.

### 2. Постоянный каталог и совместимость

Один новый app-owned каталог `Application Support/MeetingCompanion/VoiceProfiles/`,
не внутри папки записей/native-models/runtime. Один атомарно заменяемый JSON
документ v1 содержит людей, bounded образцы, агрегаты, pending learning events,
отзывы и поколения. Данные без аудио; каталогу не нужна новая СУБД. File lock,
revision и сравнение исходных bytes защищают от второго писателя. На диске private
user permissions, пути с containment/symlink проверкой, ошибки без reset/fallback.

| Сущность | Существенные поля |
| --- | --- |
| Person | UUID, displayName, явно подтверждённые calendar bindings, generation |
| Sample | UUID, personID, normalized vector, embeddingSpaceID, duration, recording/result/turn/source, interval, PCM hash, assignmentID/version, policyID |
| Profile | centroid, active sampleIDs, состояние, версия политики; отдельно состояние последней попытки обновления |
| Learning event | eventID, sequence, assignmentID, expected/result edits fingerprints, previous/new person/origin, targets, stage, outcome, catalogue/person generations |

PersonID не является именем, путём, speakerID или attendee index. Recording
reference использует канонический locator и result identity; перенос/переименование
папки не создаёт новый вклад при совпадении assignmentID/PCM. Evicted образцы
не возвращаются от повтора старого события. Сохраняются обработанные assignment
cursors/отзывы для идемпотентности; их безопасная компакция не удаляет pending
events или fence последнего исправления. Предел 12 относится к эталонам человека,
не ко всем метаданным базы; реальный размер измеряется, а не обещается константой.

`edits.json` v2 добавляет provenance к name override: assignmentID, personID,
origin (`manual`, `automaticVoiceMatch`, `derivedVoiceMatch`, `legacyManualImport`),
версию назначения и pending learning events того же commit.
Каждый save сохраняет все ещё не подтверждённые каталогом события; compaction
superseded событий сохраняет их обязательства отзыва. Text-only не создаёт
новое назначение и не очищает outbox.
Чтение v1 остаётся; имена v1 имеют unknown origin. Переход на v2 выполняется
атомарно при первом provenance-aware name commit, не при чтении. Text-only save
v1 не требует миграции, v2 сохраняет весь provenance. Старое приложение должно
отклонять v2 по уже существующей unsupported-version policy; downgrade после
такой правки не обещает редактирование. Не пытаться стирать v2 ради отката.

Если более ранняя сборка уже добавила эталоны из старой разметки, её отметка
в файле блокировки требует координировать последующие правки имени. ID для
отзыва v1 вычисляется из resultID, turnID и сохранённого имени. Для v2 используется
сохранённый assignmentID.

Альтернатива additive provenance в v1 отклонена: старая версия могла бы молча
выкинуть неизвестные поля и превратить собственные подсказки в неизвестные имена.

### 3. Два commit и восстановление learning

Application координирует сохранение имени и каталог; worker не пишет ни один из
них. Для операций, затрагивающих обучавшийся вклад, отзыв действует и при
выключенной функции: выключение отменяет извлечение, а не корректность базы.

Порядок для cooperating app writers:

1. За существующим recording writer lock зафиксировать previous edits bytes,
   result/assignment и target snapshot. Создать assignmentID и следующий
   последовательный learning event. Порядок коротких транзакций: recording gate,
   затем catalogue gate; не держать catalogue lock во время inference/await.
2. До edits commit атомарно сохранить event `prepared` во внешнем каталоге.
   Прежние затрагиваемые вклады пометить `suspended` (не участвуют в scoring).
   Это write-ahead fence, не свидетельство успешной новой разметки.
3. Тем же recording save/CAS атомарно записать имя, provenance v2 и outbox event
   с прежним/новым назначением. Это commit имени. Проверенный финальный fingerprint
   и assignment evidence перенести
   в event `committed` до освобождения координируемого recording gate.
4. `committed` фиксирует отзыв прежнего вклада и возможность отбирать новый.
   Ошибка обновления каталога после edits commit не откатывает имя: показать
   saved имя и «Профиль не обновлён», оставить `prepared` для reconciliation.
5. Общий исполнитель читает актуальные source/assignment snapshots и извлекает
   признаки. Каталог одним commit активирует допустимые эталоны, centroid и
   terminal outcome события. Дубликат eventID/assignment/PCM не увеличивает вес.

Если write-ahead недоступен до name commit, базовое сохранение имени разрешено:
outbox вместе с именем остаётся в edits v2, learning показано как неуспешное.
До успешного переноса события и отзыва в каталог voice capability в процессе
блокируется. На запуске перед scoring выполняется metadata-only reconciliation
активных source references и v2 outbox текущей стандартной библиотеки, без
импорта старых имён или моделей. Событие из edits копируется наружу идемпотентно,
только после проверки сохранённого assignmentID/version/origin. Перенос текущего
result в historical при retry также требует предварительного переноса его outbox.
При обновлении библиотеки ProcessingService выполняет сверку с открытыми writer
редактора и retry. Актор сохраняет набор retry writer на время сверки. Ошибка
по одному результату хранится с его resultID, ошибки обхода относятся к записи.
Outbox записи не является единственной копией уже принятого каталогом события.
Удалять/компактировать его можно только после durable acknowledgement каталога.

| Сбой/состояние | Восстановление перед сопоставлением |
| --- | --- |
| `prepared`, edits точно равны previous snapshot | save не состоялся; отменить event и восстановить прежние допустимые образцы |
| `prepared`, edits содержат тот же assignmentID/version | повысить до committed, отозвать старое, продолжить при включённой функции |
| более позднее назначение того же turn | прежнее событие superseded; старый вклад отозван, обработать только последнее |
| `prepared`, edits недоступны/исход неизвестен | оставить затронутые вклады suspended, новые не активировать |
| `committed`, аудио исчезло | отзыв завершить без аудио, extraction отметить skipped; другие эталоны сохранить |
| каталог commit выполнен, terminal ack потерян | idempotent повтор по event/assignment/PCM без добавления веса |
| человек/каталог удалён | generation fence отклоняет прежние jobs/events; автоматического replay нет |

Удаление записи/очистка источника приложением и новый retry проходят ту же recording admission
boundary: до удаления/teardown сверить `prepared` с ещё доступными правками и
вынести committed evidence/отзывы, включая edits outbox, наружу. Если эту гарантию завершить нельзя,
удаление не начинать, объяснить ошибку. Extraction можно отменить, отзыв — нет.
После этого deletion не ждёт модели и не удаляет каталог. Не-cooperating внешнее
удаление в окне сбоя между edits commit и переносом outbox не входит в гарантию
транзакции cooperating writers: утраченное событие восстановить невозможно.
Для известного `prepared` с неизвестным исходом — безопасно suspended, не
фиктивное подтверждение. Совершившийся ранее learning без pending исправления
переживает исчезновение записи по V01, без обязательного аудио.

Эта координация обязательна для всех name mutation entry points, включая direct
Core callers/CLI: без provenance-aware coordinator они не могут менять
обучавшиеся назначения. Общий механизм в Core/Application переиспользуется,
не добавляется специальная запись файла из SwiftUI. Межпроцессный learning gate
сериализует короткие prepare/name/ack операции; lock order фиксирован и тестируется.

### 4. Отбор и ограниченное обновление

Модель — кандидат из [Swift/MLX PoC](../../../experiments/voice-identity/README.md):
WeSpeaker ResNet34-LM, 256 нормированных Float32. Использовать закреплённые там
исходники/веса и frontend fix; не портировать сеть повторно. `embeddingSpaceID`
включает weights/frontend/code/backend/dimension/normalization. `policyID`
дополнительно версионирует отбор, update/scoring. Несовместимость сохраняет данные
с «Нужно обновить профиль», не сравнивает их и не запускает пересчёт сама.

Отбор берёт фактический recognition WAV конкретного source/result, включая
применённый AEC. Не брать playback mix, микрофон как личность владельца или весь
Speaker N как одного человека при обучении. Окна распределены по времени; тишина/overlap
исключаются по имеющимся сигналам. При наличии `voice-quality.v1.json` с `evidence.speech != nil`
используются `evidence.speech` и `overlap` (для `.matching` при `evidence != nil` и `speech == nil`
возвращается `missingEvidence`). В результатах без `voice-quality.v1.json` для `.matching`
(при `diarizationStatus == .completed && (detectedVoiceCount ?? 0) > 0`) и для `.learning`
(при `evidence?.speech == nil`) интервалы речи строятся по словам `document.words` говорящего
(объединение при зазоре `<= 0.60` с для `.matching` и `<= 0.40` с для `.learning`; аналогично `evidence.speech` для `.matching` объединяет короткие паузы `<= 0.60` с, тогда как `.learning` сохраняет `maxGap = 0` на `evidence.speech`; в репликах из `> 1` слова аномально растянутые слова CTC
с длительностью `> max(2.5, 1.2 * tokens)` ограничиваются до `min(end, start + max(1.5, 0.8 * tokens))`),
без скрытого rerun диаризации; при отсутствии слов (или неподтверждённой диаризации для `.matching`)
возвращается `missingEvidence`. Для `.matching` внутри реплики `>= 3.0` с (обрезанной на `0.15` с
по краям) после вычитания `otherTurns` и `overlap` (`±0.10` с) и квантования внутрь до представимых
`Int(exactly:)` отсчётов 16 кГц по умолчанию выбирается один самый длинный чистый подотрезок `>= 48_000` отсчётов
(при равенстве — более ранний), из середины которого берётся одно окно `3.0..6.0` с (`<= 96_000`
отсчётов), а при строгой проверке смешанного кластера — до `3` непересекающихся чистых подокон 3–6 с. При наличии у говорящего окон с плотной речью
(`effectiveTokens >= windowDuration`) автосопоставление и 4-оконный лимит ручного обучения
отдают им приоритет. Оставшиеся места в квоте занимают другие чистые окна,
в том числе для проверки смешанной группы. Недостаток совместимых профилей
сохраняется как отказ сопоставления без записи каталога.

Новый Pipeline при уже выполняющейся диаризации сохраняет optional
`voice-quality.v1.json` в staging своего результата: resultID, source identities,
speech/overlap intervals, producer/policy version. Путь определяется относительно
contained result directory. Artifact immutable после публикации, его отсутствие
не меняет result.json v1. Ошибка его формирования даёт предупреждение и отсутствие
дополнительных сигналов, не срывает базовый ASR. Повреждение при чтении отклоняет
voice job, без молчаливого игнорирования/перегенерации.

Стартовые исследовательские параметры: окно 3–6 секунд, отступ 150 мс,
защита от известного чужого голоса 100 мс, минимум 3 окна/12 секунд,
до 12 active эталонов человека, не более 4 от одной встречи. Они не являются
продуктовой калибровкой. Слишком короткое/нулевое/неконечное окно, неправильные
границы и source mismatch дают определённую причину пропуска/ошибки.

Отбор/замена детерминированы для одинакового snapshot. Ограничивать вклад встречи
и сохранять представительство других условий; при первичной сборке профиля
(`compatibleActive.isEmpty`) входные кандидаты пакета приводятся к каноническому порядку
до дедупликации, оценка клики и активный `balanced` используют единый канонический порядок
и общий расчёт длительности и достаточности по фреймам 16 кГц (`48_000...96_000` на окно, `>= 192_000` фреймов / `12` с суммарно, единый с проверкой при отзыве эталонов), а при обновлении резерва
непопавшие новые кандидаты ставятся перед старыми отложенными образцами в тех же лимитах
(`<= 4` на встречу, `<= 12` всего). В поддерживаемом пределе (`<= 24` кандидатов)
выполняется точный поиск максимальной взаимно согласованной клики (`cosine >= minimumAgreement`,
`manual-v1-agreement-0.60`, `minimumAgreement = 0.60`), не зависящей от порядка входа
(приоритет: достаточность `>= 3` окна / `>= 12` с, размер клики, максимум минимального,
максимум суммы попарных сходств, канонический порядок); превышение лимита `24`
явно отклоняется без неполного эвристического ответа. Сильно противоречащие кандидаты при наличии активного
профиля не активируются до согласованной ручной разметки ещё одной встречи. Кандидаты
хранятся отдельно от активных эталонов в пределах ещё 12 окон на человека.
Активные окна выбираются по кругу между встречами. Повтор PCM или тех же
границ назначения отбрасывается. Точные
параметры согласованности/резервуара фиксируются вместе с quality policy до
blind test; не добавлять пользовательские sliders. Centroid = normalize(sum e_i)
по допустимым active эталонам; нулевая норма не создаёт рабочий профиль. Сохранить
старый агрегат при неуспешном пополнении, кроме явно отозванных его составляющих.

### 5. Сопоставление и календарь

Задание фиксирует current/root, source identity, edits/catalogue revision,
model/policy, feature/person generations. Все compatible profiles участвуют,
включая уже назначенных в другой группе и гостей. Подтверждённая calendar binding
проверяется по сохранённому контексту записи, без сетевого refresh. В новых
снимках рядом с прежним списком `attendees` сохраняются отдельные контакты
EventKit, когда доступен однозначный адрес. Обычный экспорт использует прежний
список. Контакт связывается с personID отдельным подтверждением. Старые имена,
отсутствие адреса и дубли контакта не дают календарного бонуса.

Для каждого окна `s_i = cosine(query, profile_i)`, `r_i = s_i + b_i`, `0 <= b_i <= B`.
Победитель допустим при `s_w >= T`, `r_w-r_second >= D` и `max(s_i)-s_w <= G`.
Дополнительно всегда возвращается **акустический** `strongLeader`: лидер по `s_i`
с `s_i >= T` независимо от `b_i` и `D` (даже при победе другого кандидата с бонусом).
Нужны два compatible profile; календарь не спасает акустически плохое совпадение.
`r` не вероятность; в UI не показывать «97%» из cosine/ranking.

Для неподписанных реплик (`displayName == nil`) источников с подтверждённой
диаризацией (`diarizationStatus == .completed && (detectedVoiceCount ?? 0) > 0`)
чистые подокна 3–6 с (`48_000...96_000` фреймов 16 кГц, проверка длины по точным
фреймам) на каждой дорожке жадно очищаются от пересечений по возрастанию `startFrame`
и в первичном проходе укладываются в бюджет `<= 64` окна (1 батч worker; каждый
отдельный запрос worker также ограничен `<= 64` окнами) через watershed-квоту
по группам `Speaker N` и выборку ближайших уникальных окон к равномерным временным точкам;
реплики вне квоты не получают преждевременный отказ, а группы без подтверждённой
диаризации получают `.missingEvidence`. Оценка группы `Speaker N` включает в знаменатель
все её запланированные окна, в том числе пустые (`embedding == nil`) ответы тишины.
Группа получает имя `P` (`automaticVoiceMatch`) на все свои неподписанные реплики
(включая короткие `< 3` с и с паузами, не затрагивая ручные имена), только если: во
всех окнах группы `strongLeaders == [P]` (включая как акустического лидера, так и
календарного победителя), при `windows.count >= 3` — `matchedCount(P) >= 3` и
`3 * matchedCount(P) >= 2 * windows.count` (без требования разброса по 2/3 длительности
группы), а при `windows.count in 1...2` — `matchedCount(P) == windows.count`.
При нарушении условий групповое автоназначение отменяется: при `strongLeaders.count > 1`
и отсутствии `mixedClusterRescue` все неподписанные реплики группы получают `.ambiguous`,
а при заданной `mixedClusterRescue` (`threshold = 0.65, margin = 0.20`, чисто
акустической без календарного бонуса) групповое распространение остаётся заблокированным,
а измеренные в первичном батче реплики смешанной группы проверяются по своим первичным
окнам (без повторного извлечения) и дополнительным непересекающимся чистым подокнам
3–6 с (до `3` на реплику, извлекаемым батчами `<= 64` окна с проверкой отмены и
поколений перед каждым батчем), точечно получая `automaticVoiceMatch` только при
единогласном согласии первичных окон и всех подокон (`nil`/конфликт/низкий margin и
реплики вне `plan.queries` оставляют `.ambiguous`). При совпадении дорожки,
fingerprint и границ в отсчётах все проверки окна используют один ответ worker.
В прочих
случаях выставляются причины отказа окна/отбора/группы. Автоимя не навязывает
one-to-one между группами или дорожками. Смена snapshot инвалидирует устаревший
callback до edits commit. В композиции приложения (`RecorderAppDelegate`) по решению
владельца задаётся активная политика `RecorderViewModel.defaultVoiceMatchPolicy`
(`T=0.60, D=0.15, B=0, G=0, mixedClusterRescue=0.65/0.20`).

### 6. Исполнение, cancellation и подготовка

Новые команды Application: автоназначение нового current, learning сохранённого
назначения, выключение, сброс обучения, удаление человека/базы.
Это команды существующих application services, не новый универсальный framework.
`ProcessingService` расширяется минимальным kind для ASR/voice и финальной
опциональной станцией маршрута `.voices` («Определение голосов», модель `WeSpeaker`),
добавляемой при постановке задания, если включено запоминание и задана
`voiceMatchPolicy` (`5..7` этапов против `4..6` без неё). Автоназначение
выполняется прямо внутри `startTranscription` после публикации нового `resultID`
(деля открытый `openWriter` при retry и напрямую вызывая `voiceRunner.extractVoiceEmbeddings`
без рекурсивного входа в очередь), удерживая запись в `.processing` до
сохранения `automaticVoiceMatch` и лишь затем открывая `.completed`. Любой пропуск
(`< 2` профилей, сбой библиотеки, выключение функции, устаревший результат) или
ошибка на этапе `.voices` не срывает уже опубликованный ASR: `.saving` остаётся
завершённым, `.voices` получает `.skipped`/`.failed` с причиной/предупреждением, а
общий job завершается `.completed`. Фоновое `.learning` после ручных правок по-прежнему
идёт отдельным voice-заданием очереди, не меняя статус/маршрут ASR; foreground ASR
получает приоритет перед ещё не начатым `.learning`, а выключение функции отменяет
активную подзадачу `.voices` (без отмены ASR) и все `.learning` задания.
Capture продолжает работать.

Режим worker `--voice-embeddings <recording-directory>` читает один bounded JSON
request v1 из закрываемого stdin и возвращает bounded JSON response по приватному
pipe. Запрос содержит requestID, resultID, source fingerprints и интервалы.
Platform проверяет exit code, идентификаторы, размер и норму векторов.
Векторы и имена в логи не попадают. Обычные CLI flags ASR остаются совместимы.
Неизвестный request version/модель/path mismatch — ошибка только voice job.

Platform использует тот же SubprocessRunner SIGTERM/SIGKILL и cleanup временных
артефактов. Worker читает по окнам, загружает одну voice-модель и завершает процесс;
не пишет правки или каталог. После callback повторная проверка snapshot/CAS.
Фоновые voice jobs принадлежат Application и переживают закрытие редактора.
Выключение отменяет extraction и автоназначение, сохраняет
профили и обязательства отзыва. Person/base delete повышает generation и
аннулирует старые events; успешное новое ручное назначение может создать новый
профиль, старые события сами его не воссоздают.

Voice readiness/prepare отделены от required ASR models; включение тумблера не
означает network request. Явная подготовка проверяет pinned hashes и licenses,
совместимость с текущим MLX и bundled Metal resources, без копирования PoC cache.
Модельный reset удаляет разрешённые weights, не VoiceProfiles. Отдельная кнопка
удаления базы подтверждает ровно voice данные и не удаляет транскрипты.

## Risks / Trade-offs

- [Календарь закрепляет ошибку] → ограниченные T/D/B/G, blind guests и режим без календаря.
- [Группа Nemotron содержит разных людей] → защита `strongLeaders.count > 1` (отказ
  всей группе с `.ambiguous` при втором сильном лидере `>= T`) и порог согласованных
  окон `>= 2/3` (`>= 3`); пользовательская group assignment не выдаётся за
  акустическое доказательство и ручные имена не заменяются.
- [Самообучение на ошибках] → provenance v2, машинные назначения исключены из обучения,
  лимит одной встречи и независимое подтверждение противоречащего материала.
- [Два файла не образуют общую транзакцию] → write-ahead event, атомарный edits
  outbox, suspension/reconciliation и fault-injection на каждой границе.
- [Недоступный каталог] → имя и outbox сохраняются вместе; scoring недоступен
  до reconciliation, удаление источника ждёт durable переноса события наружу.
- [Внешнее удаление в crash window] → эта некооперирующая операция вне гарантии;
  app-owned deletion/cleanup/retry обязаны пройти outbox barrier.
- [Downgrade после v2] → явная unsupported policy, без потери происхождения.
- [Удалённое аудио] → recognition остаётся; аудит/пересчёт утраченного материала невозможен.
- [Лицензия conversion отличается от original] → distribution gate до поставки весов.

## Migration Plan

1. Зафиксировать согласованные дельты ADR/SDD. До calibration утвердить показатели качества.
2. Реализовать synthetic contracts/recovery/форматы с feature default off.
   Старые записи при discovery не менять; каталог создать при явном действии.
3. Интегрировать worker и pinned weights после проверки лицензий/MLX/resources;
   сохранить ASR/test/build boundaries. Без скрытой подготовки и network.
4. Локальная сборка для владельца включает `defaultVoiceMatchPolicy` (`T=0.60, D=0.15, B=0, G=0, mixedClusterRescue=0.65/0.20`)
   и явный этап `.voices` в маршруте. Для 2.2.0 владелец одобрил выпуск
   с автоименами в экспериментальном режиме. Независимая проверка остаётся
   условием снятия экспериментального статуса. Веса загружаются при явной
   подготовке. Уведомления об исходной модели и конверсии входят в THIRD_PARTY.md.
5. Откат feature-off сохраняет v2 и профили; физическое удаление — отдельное
   явное действие. Исторические аудио/result.json/правки не откатывать и не стирать.

## Validation Strategy

Test-first на public Core/Application boundaries: v1/v2/provenance, selection,
scoring, bounded updates, duplicate/rename/correction, lock/CAS, catalogue corruption,
prepared/committed/finalized crash windows, edits outbox, delete/retry barrier,
feature-off revocation, generation/cancellation. Synthetic audio/fixtures only.
Fault injection обязана проверять observable saved имя и active samples после
рестарта, а не только последовательность вызовов mocks.

Worker contract tests: finite normalized vectors, shape/version/hash/containment,
source fingerprint до/после чтения, offline/no hidden ASR, cancellation and bounded
memory. Full quality evaluation — отдельно на разрешённых личных записях вне Git,
enrollment/calibration/blind test по целым встречам. Калибруется весь pipeline
отбора/обновления/отказа, а не только cosine на заранее чистых clips.

Native UAT: два входа общего редактора/preview, ручное имя без прослушивания,
inline обучение и отказ, оба источника, длинные имена, narrow workspace, keyboard/
VoiceOver, owned Settings/admission, capture параллельно voice job, delete/reset.
Swift checks/build/packaging из AGENTS.md; TDD и UAT задачи остаются незакрытыми.
