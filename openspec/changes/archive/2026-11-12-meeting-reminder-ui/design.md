# Дизайн и границы реализации

## Context

Baseline: master `35d00b8682e2a4e0d146f90625a9567704baae4e` (beta.36 appcast). showReminder использует отдельный nonactivating floating NSPanel; MeetingReminderView сейчас имеет фиксированные 392×212 pt внутри панели 400×220. При записи кнопка уже называется «Завершить и начать новую» и вызывает startMeeting с expectedSessionID.

## Goals / Non-Goals

Привести напоминание к существующему стилю и безопасно вместить 12+ встреч. Не менять capture/pipeline, политику коротких записей, reminder eligibility/acknowledgement/timeout, настройки, капсулу и workspace. Поиск не добавлять.

## Decisions

### Компоновка

Эталон: [reference/index.html](reference/index.html), состояние с записью — по умолчанию, без записи — `?recording=0`. Native controls и системное поведение важнее буквального копирования браузерного popover.

- Панель шириной 440 pt с учётом наружной границы; отступы 24 pt, радиус 24 pt. Высота по содержимому, отдельно для двух состояний; прежние fixed 212 pt убрать. Открытие списка не меняет frame напоминания. Длинное выбранное название переносится целиком, не обрезается фиксированной высотой.
- Максимальная высота reminder ограничена доступной областью visibleFrame с отступами 16 pt и без перекрытия controls видимой капсулы. Если содержимое выше, прокручивается текстовая область; действия остаются видимыми вне неё. Название доступно целиком прокруткой и VoiceOver, без потери primary/secondary controls. Это ограничение родителя не зависит от открытия chooser.
- SF/system typography: вводная строка 13 pt medium secondary, название 28 pt semibold с межстрочным около 1.2, время 16 pt secondary. Основные интервалы 8/12/16/24 pt.
- Idle: «Встреча начинается» → название → «Сегодня, 12:30–13:00» в локальном формате → «Другая встреча» с chevron → нижние действия: «Пропустить» слева, синяя «Начать запись» справа.
- Recording: «Начинается следующая встреча» → новая встреча и время → «Другая встреча» → разделённый тонкими линиями блок «Сейчас записывается», название текущей записи и её настоящий elapsed по существующему форматтеру → пояснение → синяя «Завершить и начать новую» на всю ширину, ниже «Пропустить». Кнопки от 44 pt по высоте; длинная основная подпись не режется.
- Для обычной текущей записи пояснение: «Завершим текущую запись и начнём новую. Обработка предыдущей продолжится в фоне». Для текущей записи короче порога отмены: «Текущая запись короче 10 секунд будет отменена. Затем начнём новую». Это раскрывает прежний showsCancelRecording/cancelShort, не меняет правило.
- Если нет календарного контекста текущей записи — её существующее отображаемое имя/«Без встречи»; названия и elapsed из shared state, не из выбранной новой встречи.

### Цвета и поверхность

Переиспользовать InterfaceStyle/существующие semantic tokens. Эталон light: surface #fff, ink #202630, secondary #626b79, primary #1762cf с белым текстом. Dark: surface #20242b, ink #f0f2f6, secondary #a4adbc, primary #8ab9ff с тёмным текстом #15243b. Нейтральная граница/спокойная тень; красная точка только рядом с текстом «Сейчас записывается». Статусы различимы без цвета. Существующий MeetingOverlaySurface и native materials адаптировать без прямоугольного halo. Системная тема, keyboard focus, VoiceOver и reduced motion сохраняются.

### Выбор из 12 и более встреч

Отдельный native popover/menu у «Другая встреча», не VStack внутри reminder. Ширина до 360 pt, высота до 420 pt и не более доступного visibleFrame минус 16 pt по краям. Примерно пять строк + постоянный «Без встречи»; остальные доступны вертикальным скроллом. На низком экране список уменьшается. Поповер открывается вниз либо вверх по доступному месту и не выходит за экран.

Строка: галочка выбранной встречи слева, название и время двумя уровнями; минимум 60 pt, длинное название переносится. «Без встречи» закреплено снизу после разделителя. Без поиска, счётчиков, фильтров и новых настроек. Порядок и состав кандидатов — прежние calendar.events правила: исключить recordingMeetingID, сохранить выбранный fallback, если он уже отсутствует в events. Не заменять полный список только «ближайшими» из HTML.

При открытии выбранная строка видна и получает focus. Up/Down перемещают focus, Enter/Space выбирают. Только явный выбор изменяет reminderMeeting; Escape и клик снаружи закрывают без изменения выбора. После выбора — закрыть popover и вернуть focus на «Другая встреча». Отдельной activation приложения при автоматическом показе нет; явный клик допускает native keyboard input без global key hook.

### Действия и lifecycle

Оба primary используют существующий startMeeting(selected, expectedSessionID), зафиксированный именно для этого reminder. Не создавать второй stop/start путь или новую session. При нормальной записи — дождаться её stop/finalization по прежнему пути и только затем запускать новую; previous processing не является условием завершения новой формы. При short cancellation — прежняя отмена, а не обещание сохранения.

Существующий общий путь разрешено минимально доработать: до stop отклонять исчезнувшую либо изменённую выбранную встречу (одинаковый id не означает неизменность контекста). После ожидания stop и перед новым capture повторно проверить актуальность выбранного контекста, session identity и modal/busy/diagnostic/admission. Проверки нужны на границе действия после асинхронных ожиданий, а не только по состоянию кнопки. Если во время stop появилась Settings/native modal, встреча изменилась или session уже занята другой записью, новая запись не запускается. Уже завершённую запись не возобновлять; её данные и общая обработка остаются по прежнему lifecycle. Test seams используют только синтетические данные и не обращаются к личному календарю или аудио.

«Пропустить» и существующий timeout закрывают только reminder с его popover; capture и processing продолжаются. Родительский reminder не исчезает с оставшимся отдельно списком. Продолжительность timeout и calendar acknowledgement не меняются. При нормальном ожидании, ручном скрытии/смене контекста и новом reminder старые callbacks не действуют на новую панель/session.

Повторные нажатия не создают параллельных start/stop. Сохранить busy/diagnostic/sessionStarting/sessionStopping/modal guards и проверку актуальности встречи. Если встреча удалена/изменилась либо session уже другая — показать понятную конкретную причину; не останавливать новую чужую session. Ошибка stop не запускает новую запись; ошибка start не показывает ложную активную запись. Использовать реальные outcomes, без выдуманных успешных статусов.

Видимая поверхность ошибки — terminal-состояние той же native reminder panel: заголовок «Не удалось начать запись», конкретная причина и единственная кнопка «Закрыть». Выбор встречи и primary отсутствуют; повторной попытки внутри этого состояния нет. Ошибка видна и при скрытом workspace; запись errorMessage только в скрытую форму недостаточна. Не открывать новую форму и не активировать приложение автоматически; существующий modal/input сохраняется. «Закрыть» убирает только reminder и его chooser. Поздний outcome старой панели не заменяет новое напоминание и не меняет новую session.

После ошибки попытка закончена. Пользователь может заново войти через существующее действие записи и явно начать новую попытку с актуальными session/meeting/admission checks. Не добавлять автоматические повторы, fallback-пути, возврат к незавершённому шагу или восстановление workflow. Если stop завершился, а start не удался, предыдущую запись автоматически не возобновлять. Сохранность аудио и результатов, предусмотренная прежним lifecycle, обязательна; согласованное правило отмены short recording сохраняется.

Сохранённый в списке выбранный fallback — только отображение ранее выбранного контекста. Отсутствие либо изменение встречи в актуальном календаре не разрешает запуск устаревшего контекста или обход проверки.

Показ, выбор и таймер reminder не скрывают активную капсулу записи/обработки и не перехватывают focus/Space автоматически. Позиция панели в visibleFrame рядом с капсулой, без перекрытия её controls: использовать фактические размеры вместо прежних предположений о высоте 220 pt.

## Risks / Trade-offs

- Длинные названия → content-driven высота с экранным максимумом, scroll текстовой области при переполнении и доступные действия; chooser прокручивается отдельно. Native visual check на малом экране.
- Session меняется, пока reminder открыт → сохранить expectedSessionID и поздние guards; не трактовать новый isRecording как разрешение остановить другую session.
- Сохранение/обработка короткой записи не гарантируется → явное пояснение по действующему правилу, без изменения данных/политики.

## Migration Plan

Только native UI поверх прежнего lifecycle. Нет новых persistence keys или data migration; rollback — revert этого UI change. Не изменять старые архивные SDD.

## Open Questions

Продуктовых вопросов нет. Выбрать существующий native механизм popover/menu, позволяющий ограничить высоту и работать клавиатурой; решение не требует нового окна приложения или сервиса.
