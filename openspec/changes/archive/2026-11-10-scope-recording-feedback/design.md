# Причина и минимальное исправление

`RecorderViewModel.handleProcessingEvent` получает job с recording URL, но пишет
terminal warning в общий `RecordingHistory.error`. Баннер в `RecordingHistoryView`
не проверяет принадлежность сообщения. Успешное завершение другой записи и
смена selection не делают старое сообщение подходящим к новой встрече.

Исправление остаётся в существующей цепочке feedback: сохранить принадлежность
сообщения записи и учитывать её при показе баннера. Использовать ту же canonical
recording identity, что selection/jobs/history. Проверить все затронутые пути
записи ошибки, чтобы прямое присваивание не сохраняло чужой owner.

Общее `error` остаётся отдельным. Transient сообщения по canonical URL хранятся
в существующем `RecordingHistory`, чтобы независимые события A/B не затирали
друг друга или общую ошибку. Текущий `persistenceWarning` берётся из выбранного
entry, без копирования snapshot warning в общий баннер. Показ объединяет общую
и собственную ошибку, убирая одинаковые строки. Принятый явный retry очищает
только прежний transient feedback своей записи; сохранённые warnings не стираются.

Один сброс при переключении недостаточен: job A может закончиться, пока открыта B.
Не отбрасывать все предупреждения и не скрывать общие ошибки библиотеки. Сохранённые
`RecordingEntry.problems` и предупреждения current JSON продолжают принадлежать
своей записи и остаются доступны при её открытии. Существующие области transcript
warnings/processing details, capsule и operation feedback переиспользуются.

Новая база, глобальный notification manager, persistence keys, таймер очистки,
повторное распознавание и изменение порогов диаризации не нужны. Отдельно
сохранить global feedback без recording owner, например ошибку чтения библиотеки.

## Проверка

На synthetic A/B проверить: warning A → открыть B без warning → вернуться к A;
позднее terminal event A при открытой B; warning A при открытой A; общую ошибку
библиотеки; неизменность selection/current и файлов. RED должен пройти через
production event/selection/rendering boundary, а не проверять только новый helper.
Реальный результат, послуживший диагностикой, не редактируется и не распознаётся заново.

Native UI проверяется на синтетических данных; установленную сборку проверяет
владелец. VoiceOver/CUA не запускаются. Физическая UAT не подменяется source review.
