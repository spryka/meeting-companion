## Purpose

Сохранение структурированных расшифровок и пользовательских изменений для повторного открытия, редактирования и экспорта без потери исходного результата.

## ADDED Requirements

### Requirement: Independent structured output
Система SHALL сохранять структурированный результат каждой успешно обработанной новой записи независимо от включения Parakeet, с версией формата, идентификатором результата, репликами, словами, временем и источниками голосов.

#### Scenario: Parakeet disabled
- **WHEN** обработка завершена с выключенным Parakeet
- **THEN** доступны структурированный результат и обычный TXT с одинаковым распознанным текстом
- **AND** слова имеют конечные неотрицательные интервалы start <= end и идентификаторы источника

#### Scenario: Overlapping speech
- **WHEN** две дорожки содержат одновременную речь
- **THEN** обе реплики и их исходные интервалы сохранены без последовательного сдвига времени

### Requirement: Stable identities within a result
Система SHALL сохранять ID реплики в пределах версии результата и определять голос парой источник/локальная метка. Имена людей SHALL храниться отдельно от меток модели. В интерфейсе и экспорте неназначенные голоса SHALL иметь уникальные в пределах результата номера Speaker N; одинаковые локальные номера разных источников SHALL не отображаться как одна группа.

#### Scenario: Same labels on different sources
- **GIVEN** до объединения оба источника имеют локальные метки Speaker 1 и Speaker 2
- **WHEN** система объединяет результаты дорожек
- **THEN** микрофонные группы отображаются как Speaker 1 и Speaker 2, системные как Speaker 3 и Speaker 4
- **AND** внутренние ключи сохраняют источник и локальную метку
- **AND** редактирование одной группы не изменяет вторую

### Requirement: Versioned recognition baseline
Каждая версия SHALL независимо сохранять исходные слова GigaAM и итоговые слова после необязательной коррекции, состояния обработки по источникам и предупреждения. Повторная обработка SHALL не изменять baseline предыдущей версии. Число обнаруженных голосов SHALL отличать неизвестное значение от подтверждённого нуля и сохраняться до назначения голосов словам.

#### Scenario: Correction succeeds
- **WHEN** Parakeet изменяет текст распознавания
- **THEN** версия содержит исходные слова GigaAM и итоговые слова с их интервалами
- **AND** чтение baseline не зависит от внешнего журнала коррекции

#### Scenario: Partial correction failure
- **WHEN** коррекция одного источника или сохранение её журнала завершается ошибкой
- **THEN** источник сохраняет baseline GigaAM и итоговый текст согласно существующему fallback конвейера
- **AND** версия содержит предупреждение и фактическое состояние коррекции каждого источника

#### Scenario: Retry preserves baseline
- **WHEN** повторная обработка использует другие настройки Parakeet
- **THEN** baseline, итоговые слова и предупреждения предыдущей версии остаются неизменными

#### Scenario: Empty source and unknown voice count
- **WHEN** источник не содержит распознанных слов
- **THEN** он сохраняется без выдуманных слов и реплик
- **AND** успешная диаризация без голосов имеет число 0, а отключённая или неуспешная — неизвестное число

### Requirement: Durable edits
Система SHALL сохранять текстовые правки и назначенных говорящих отдельно от неизменяемого результата распознавания. Повторное открытие SHALL восстанавливать последнее успешно сохранённое состояние без запуска моделей.

#### Scenario: Reopen edited result
- **WHEN** пользователь сохраняет текст и имя, закрывает приложение и открывает ту же запись
- **THEN** видны сохранённые правки, а исходное распознавание остаётся доступным

#### Scenario: Failed save
- **WHEN** запись пользовательских правок завершается ошибкой или прерывается
- **THEN** последняя корректная сохранённая версия остаётся читаемой
- **AND** приложение не сообщает об успешном сохранении, сохраняет несохранённый текст в открытом редакторе и позволяет повторить сохранение

#### Scenario: Existing external edit
- **GIVEN** после загрузки правок внешний процесс изменил, создал или удалил файл правок
- **WHEN** редактор проверяет файл перед сохранением
- **THEN** изменение revision или содержимого блокирует сохранение и предлагается перечитать файл
- **AND** локальный ввод остаётся доступным

#### Scenario: Second application writer
- **GIVEN** один экземпляр приложения удерживает блокировку записи для редактирования
- **WHEN** второй экземпляр открывает эту запись
- **THEN** он не получает доступ на запись и показывает причину

Поддерживаемая модель SHALL ограничиваться писателями приложения, соблюдающими блокировку. Одновременное внешнее изменение программой, игнорирующей блокировку, не входит в гарантию обнаружения конфликтов.

### Requirement: Recognition version isolation
Повторное распознавание SHALL создавать отдельную версию результата и не перезаписывать предыдущие версии и правки. Автоматический перенос правок между версиями SHALL отсутствовать. По current authority ADR0004 и [refresh W01/W04](../../../refresh-macos-interface/specs/desktop-workspace/spec.md) GUI SHALL показывать только current без selector/history; immutable версии на диске сохраняются.

#### Scenario: Successful retry
- **WHEN** повторное распознавание успешно завершилось
- **THEN** новый immutable result становится единственным current; modal input разрешён явным Save/Cancel по refresh W04.9, затем прежняя review session закрыта до enqueue
- **AND** предыдущие файлы и правки сохранны без UI доступа и без переноса на новый resultID
- **AND** запрос при modal input не enqueue; editable reopen запрещён до terminal teardown, CAS/result identity/stale callbacks сохраняются без отдельного cross-window prompt

#### Scenario: Failed retry
- **WHEN** повторная обработка завершилась ошибкой
- **THEN** до directory commit прежний current с правками остаётся доступным; после commit новый current сохраняется с предупреждением

### Requirement: Complete immutable publication
Система SHALL публиковать версию атомарно после staging result.json, per-result transcript.txt, baseline, предупреждений, использованных источников и окончательного состояния микса. Staging SHALL не становиться current. После публикации файлы результата и микс SHALL не изменяться; пользовательские правки остаются отдельными.

#### Scenario: Interrupted publication
- **WHEN** публикация прерывается до атомарного завершения
- **THEN** staging-каталог исключён из current resolution, предыдущий результат и правки доступны

#### Scenario: Mix preparation failure
- **WHEN** распознавание завершилось, но подготовка или проверка микса не удалась
- **THEN** публикуется текстовая версия с недоступным миксом и сохранённым предупреждением
- **AND** поздняя попытка подготовки не изменяет эту версию

#### Scenario: AEC intermediate overwritten on retry
- **GIVEN** опубликованная версия использовала обработанный AEC микрофон
- **WHEN** повторная обработка заменяет рабочую AEC-копию
- **THEN** обработанный источник и микс опубликованной версии остаются неизменными

### Requirement: Safe format handling
Система SHALL открывать TXT без структурированного документа только для чтения с отметкой старого формата. Повреждённый или неподдерживаемый документ SHALL вызывать понятную ошибку без перезаписи файлов.

#### Scenario: Legacy transcript
- **WHEN** для записи есть только старый TXT
- **THEN** текст доступен, а редактирование и синхронные переходы из текста отключены
- **AND** для canonical записи обычное открытие доступного аудио остаётся возможным; placement проверяется по ADR0005: flat entry допускает только list и собственный contained standalone saved TXT read-only, без audio/structured lookup, retry или mutation; canonical retry отдельно требует exact contained raw originals

#### Scenario: Unsupported document version
- **WHEN** версия формата новее поддерживаемой или структура некорректна
- **THEN** показана причина недоступности редактора и доступен TXT при его наличии
- **AND** документ и правки не изменяются

#### Scenario: Invalid structured references
- **WHEN** документ содержит дублирующиеся ID, неизвестные ссылки, неконечные или неверные интервалы либо аудиопуть за пределами папки записи, включая symlink
- **THEN** документ отклоняется с понятной причиной без изменения файлов
