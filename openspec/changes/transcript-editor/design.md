# Design

## Context

См. [proposal.md](proposal.md). Сейчас история открывает TXT и Quick Look раздельно.
Python возвращает токены с временем, но общий конвейер не сохраняет постоянный
структурированный документ для всех запусков. Подробные токены есть в журнале
коррекции при включённом Parakeet. Эти журналы не становятся контрактом редактора.

## Goals / Non-Goals

Обеспечить воспроизводимое открытие и безопасное сохранение локального результата.
Первая версия подсвечивает абзацы. Исправленный текст не получает выдуманные
пословные таймкоды. SQLite, миграция старых TXT и автоматический перенос правок
между запусками распознавания не входят в первую реализацию.

## Decisions

Действующее ограничение: [ADR-0001](../../../adr/0001-preserve-recognition-and-user-edits.md).
Выбор JSON ниже является предложением реализации, а не отдельным принятым ADR.

### Документ и версии

Предлагается каталог `raw/transcripts/<result-id>/` внутри папки записи.
`result.json` неизменяем: schemaVersion, resultID, createdAt, sources, speakers,
words, turns. Источник имеет ключ host/remote, относительный путь к аудио и
фактическое число найденных моделью голосов. Голос определяется source/localID.
Слово хранит start/end/text и голос; реплика хранит ID, интервал, голос и IDs слов.
ID стабильны внутри результата, но не обещают соответствия между версиями.

`edits.json` хранит schemaVersion, resultID, revision и текущие overrides по turnID:
text и displayName. При открытии читаются результат и overrides, модели не запускаются.
Назначение группе записывается как одна операция над конкретными репликами, поэтому
последующее назначение одной реплике не затрагивает остальные. Undo в пределах
сеанса восстанавливает предыдущее состояние этой операции.

JSON выбран для переносимости папки записи и небольшого числа локальных записей.
SQLite разумно пересмотреть при общей поисковой индексации или нескольких писателях.
Формат и репозиторий документов должны позволять сменить хранение без изменения UX.

### Сохранение и повторная обработка

Один редактор на запись, повторное открытие фокусирует его. Запись edits сериализована,
с проверкой revision, через временный файл и атомарную замену. Сохранённость
показывается только после успешной операции. При конфликте внешнего изменения
сохранение блокируется с предложением перечитать файл, локальный ввод остаётся.
Валидация проверяет версию формата, ссылки на существующие ID, конечность интервалов
и разрешение аудиопутей внутри папки записи, включая символические ссылки.

Новый результат сначала готовится во временном каталоге, проверяется и публикуется
атомарно. Незавершённые каталоги не предлагаются в выборе версий. Выбранный resultID
сохраняется в состоянии истории: новый результат не переключает открытый редактор.
При первом открытии без выбора берётся последний успешно опубликованный результат.
Старые версии не удаляются автоматически. Существующий TXT остаётся совместимым
экспортом машинного результата; экспорт пользовательских правок всегда отдельный.

### Окно и плеер

История: выбранная запись -> "Открыть расшифровку" -> отдельное окно.
Вверху название и выбор версии (если их несколько), в центре лениво отображаемые
абзацы, внизу плеер с общей временной шкалой. Таймкод запускает фрагмент,
метка голоса открывает назначение имени, карандаш открывает текстовый редактор.

AVFoundation обслуживает воспроизведение из файлов. Для "Обе дорожки" используется
синхронизированный микс M4A, для отдельных источников WAV. Микрофон по умолчанию
означает файл, использованный при распознавании (AEC-копию, если она есть); источник
явно подписан. При отсутствии микса доступны существующие одиночные дорожки,
приложение не создаёт новый микс автоматически. Позиция сохраняется при переключении.
Периодический observer работает только во время воспроизведения; пауза и закрытие
останавливают обновления. Индекс интервалов выбирает все активные реплики,
при перекрытии автоскролл ведёт к первой в порядке отображения.

CJM: найти запись -> открыть -> прослушать спорную фразу -> назначить говорящего
(одна реплика по умолчанию) -> исправить текст -> сохранить -> экспортировать.
При ошибке аудио остаётся текст; при ошибке сохранения остаётся редактор с вводом.
При переходе на старый TXT показывается режим только для чтения.

### Проверки

Python: сериализация документа при Parakeet on/off и частичном сбое коррекции,
сохранение перекрытий, публикация результата. Swift: декодирование и валидация,
overrides и версии, атомарное сохранение с внедрённой ошибкой, undo, экспорт,
выбор активных интервалов, состояния автоскролла. Синтетические данные для CI.
UAT: реальный звук и seek, исчезнувший файл, светлая/тёмная тема, клавиатура,
VoiceOver, перекрытия дорожек, запись на 8 часов и повторное открытие правок.

## Risks / Trade-offs

- Таймкоды ASR приблизительны: сверять переходы на реальном аудио, не обещать точности слова.
- JSON переписывается при сохранении: писать только overrides, загрузку результата выполнять вне главного потока.
- Переименование группы может заменить ручные назначения: показать число затронутых реплик и дать undo.
- В одной реплике могут оказаться разные люди: разделение реплики отложено, имя не считается доказанной личностью.
- Предложение хранения пока не проверено прототипом: данные и UAT идут до полировки UI.

## Migration Plan

Сначала постоянный документ и тесты совместимости, затем просмотр, затем правки.
Старые файлы автоматически не мигрируются. Старое приложение продолжит читать TXT
и игнорировать новый каталог; откат не удаляет документы. Публикация релиза отдельно.
