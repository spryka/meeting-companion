# Design

## Context

См. [proposal.md](proposal.md). Сейчас история открывает TXT и Quick Look раздельно.
Python возвращает токены с временем, но общий конвейер не сохраняет постоянный
структурированный документ для всех запусков. Подробные токены есть в журнале
коррекции при включённом Parakeet. Эти журналы не становятся контрактом редактора.

## Goals / Non-Goals

Обеспечить воспроизводимое открытие и безопасное сохранение локального результата.
Первая версия подсвечивает абзацы. Исправленный текст не получает выдуманные
пословные таймкоды. SQLite, миграция старых TXT и автоматический перенос правок
между запусками распознавания не входят в первую реализацию. Переключение
источников прослушивания не входит в интерфейс: плеер воспроизводит один микс.

## Decisions

Действующее ограничение: [ADR-0001](../../../adr/0001-preserve-recognition-and-user-edits.md).
Выбор JSON ниже является предложением реализации, а не отдельным принятым ADR.
Контракт JSON v1 и файловая структура согласованы с сопровождающим (2026-10-31) как
язык-независимая спецификация формата и хранилища (ADR-0001 сохраняет силу,
перезапись корневого ADR не требуется).

### Документ и версии

Предлагается каталог `raw/transcripts/<result-id>/` внутри папки записи.
`result.json` неизменяем: schemaVersion, resultID, createdAt, sources, speakers,
words, turns. Источник имеет ключ host/remote, относительный путь к аудио и
фактическое число найденных моделью голосов. Голос определяется source/localID.
Слово хранит start/end/text и голос; реплика хранит ID, интервал, голос и IDs слов.
ID стабильны внутри результата, но не обещают соответствия между версиями.
Для отображения и экспорта сохраняется уникальный displayNumber: микрофонные
номера остаются прежними, системные смещаются на максимальный микрофонный номер
(минимальное смещение 1, как в текущем merge_sources). Внутренний ключ source/localID
не меняется при назначении имени. Номер не означает установленную личность.
Документ также хранит относительный путь к миксу своей версии, использованные
аудиоисточники и признак AEC, а также доступный сохранённый календарный контекст.

#### Контракт JSON v1

До интеграции Python и Swift используют один набор синтетических fixtures; полное
описание типов и допустимых значений хранится рядом с ними в документации формата.
Обязательные поля `result.json`:

- `schemaVersion`: целое число 1; `resultID`: непустой уникальный ID версии;
  `createdAt`: дата RFC 3339 с часовым поясом.
- `sources`: массив источников с уникальным `id` (`host` или `remote`),
  `originalAudioPath`, `recognitionAudioPath`, `diarizationStatus`
  (`completed`, `disabled`, `failed`) и `detectedVoiceCount` (целое 0–8 либо null).
  Ноль означает успешное определение отсутствия голосов; null — число неизвестно
  или диаризация отключена. Это число до назначения голосов словам.
- `speakers`: массив с уникальными `id`, парой `sourceID`/`localID` и положительным
  уникальным `displayNumber`. Локальная метка — положительное целое; запасная метка
  при сбое диаризации не означает обнаруженный голос.
- `words`: массив итоговых слов с уникальными `id`, `speakerID`, `start`, `end`,
  `text`; `turns`: массив с уникальными `id`, `speakerID`, `start`, `end`, `wordIDs`.
  Текст реплики получается соединением текстов её слов одним пробелом. Все ссылки
  существуют, слова реплики принадлежат её голосу, каждое итоговое слово входит
  ровно в одну реплику. Интервалы конечны, неотрицательны, start <= end; интервал
  реплики охватывает её слова. Перекрытия между репликами допустимы.
- `baselineWords`: исходные слова GigaAM с теми же полями, что у `words`, но
  собственным пространством ID. При выключенном или неуспешном Parakeet текст и
  интервалы совпадают с итоговыми. Соответствие ID baseline и итоговых слов не
  предполагается. `correctionStatus` по источнику: `disabled`, `completed`, `failed`.
- `aec`: `requested` (boolean), `outcome` (`disabled`, `applied`, `bypassed`, `failed`).
  `recognitionAudioPath` указывает фактически использованный микрофон; для applied
  это неизменяемая копия внутри версии, для остальных исходный микрофон.
- `playback`: `status` (`ready`, `unavailable`) и `mixPath` (относительный путь либо
  null). Для ready путь обязателен; для unavailable он null и есть предупреждение.
- `warnings`: массив объектов `code`, `sourceID` (host/remote либо null для всей
  записи), `message`. Здесь сохраняются предупреждения захвата, распознавания,
  коррекции, AEC, лимита голосов и подготовки микса; технические детали с путями
  остаются в логах, а не в пользовательском сообщении.
- `context`: null либо снимок доступных полей календаря: `title`, `startAt`
  (RFC 3339 с часовым поясом), `timeZone`, `agenda`, `attendees` (массив имён).
  Отсутствующие поля внутри объекта опускаются.

Массивы слов, реплик и голосов могут быть пустыми: тишина не создаёт выдуманную
реплику. Идентификаторы — непустые строки; повторяющиеся ID и неизвестные ссылки
отклоняются. Пути разрешаются относительно папки записи, включая проверку symlink.
Неизвестная schemaVersion отклоняется; неизвестные дополнительные поля версии 1
игнорируются. Обязательные поля не подменяются значениями по умолчанию.

Baseline каждой версии сохраняется независимо от внешних `*.gigaam.txt` и журналов
коррекции, которые остаются совместимыми служебными выходами конвейера. Токены
донора и полный журнал предложений Parakeet не нужны для открытия редактора;
сохранение baseline не зависит от успешной записи такого журнала.

`edits.json` хранит schemaVersion, resultID, revision и текущие overrides по turnID:
text и displayName. При открытии читаются результат и overrides, модели не запускаются.
В v1 revision — неотрицательное целое, overrides — объект с существующими turnID
в качестве ключей. Поля text и displayName необязательны: отсутствие означает
исходное значение; text — строка, включая пустую, displayName — непустая строка.
Удаление displayName возвращает метку Speaker N. resultID обязан совпадать
с открытым результатом. Неизвестная версия и некорректные overrides отклоняются
без изменения файлов.
Назначение группе записывается как одна операция над конкретными репликами, поэтому
последующее назначение одной реплике не затрагивает остальные. Undo в пределах
сеанса восстанавливает предыдущее состояние этой операции.

JSON выбран для переносимости папки записи и небольшого числа локальных записей.
SQLite разумно пересмотреть при общей поисковой индексации или нескольких писателях.
Формат и репозиторий документов должны позволять сменить хранение без изменения UX.

### Сохранение и повторная обработка

Один редактор на запись, повторное открытие фокусирует его. Запись edits сериализована,
с проверкой revision, через временный файл и атомарную замену. Сохранённость
показывается только после успешной операции. При конфликте внешнего изменения
сохранение блокируется с предложением перечитать файл, локальный ввод остаётся.
Поддерживается один писатель приложения на запись: репозиторий удерживает
эксклюзивную блокировку записи на время редактирования; второй экземпляр приложения
не получает режим записи. Отсутствие edits соответствует revision 0, успешная
запись увеличивает revision на 1. Перед заменой проверяются revision и отпечаток
прочитанного содержимого, включая создание/удаление файла. Это обнаруживает уже
произошедшее внешнее изменение, но не является compare-and-swap с произвольным
внешним редактором: одновременная запись программой, игнорирующей блокировку,
не поддерживается. Атомарная замена защищает от частичного JSON, а не от такой гонки.
Валидация проверяет версию формата, ссылки на существующие ID, конечность интервалов
и разрешение аудиопутей внутри папки записи, включая символические ссылки.

Новый результат сначала готовится во временном каталоге, проверяется и публикуется
атомарно. Незавершённые каталоги не предлагаются в выборе версий. Выбранный resultID
сохраняется в состоянии истории: новый результат не переключает открытый редактор.
При первом открытии без выбора берётся последний успешно опубликованный результат.
Старые версии не удаляются автоматически. Существующий TXT остаётся совместимым
экспортом машинного результата; экспорт пользовательских правок всегда отдельный.

Порядок публикации: получить распознавание и baseline -> закрепить фактически
использованную AEC-копию в staging-каталоге версии -> подготовить и проверить микс ->
сформировать окончательный result.json -> проверить комплект -> атомарно
переименовать каталог. Сбой смешивания завершает версию с playback.unavailable и
предупреждением, не отменяя текст. Опубликованная версия не дополняется миксом
задним числом; новая подготовка создаёт новую версию. При сбое публикации старые
версии и выбор остаются неизменными. Фиксированное рабочее имя AEC-копии не
используется как ссылка на обработанное аудио ранее опубликованной версии.

### Окно и плеер

История: выбранная запись -> "Открыть расшифровку" -> отдельное окно.
Вверху название и выбор версии (если их несколько), в центре лениво отображаемые
абзацы, внизу плеер с общей временной шкалой. Таймкод запускает фрагмент,
метка голоса открывает назначение имени, карандаш открывает текстовый редактор.

AVFoundation воспроизводит один готовый синхронизированный микс M4A выбранной
версии. Микс готовится в конвейере обработки из системного звука и фактически
использованного для ASR микрофона: после AEC при outcome=applied, иначе исходного.
Включённая настройка не доказывает применение AEC. При сбое сохраняется failed
и предупреждение; при обходе из-за нулевой системной дорожки — bypassed.
Сохраняются общая шкала, паузы и перекрытия. Исходный микрофон остаётся
нетронутым. Микс версии хранится рядом с result.json и не перезаписывается при
повторной обработке; исходный микс записи также не заменяется. Уже существующий
микс допустим только при подтверждённом соответствии версии и обработке микрофона.
Создание микса проверяется до публикации; при сбое текстовый результат сохраняется
с предупреждением, плеер недоступен. Открытие редактора не запускает AEC или
смешивание заново и не подставляет исходную дорожку либо микс другой версии.
Переключателя источников в плеере нет.
Периодический observer работает только во время воспроизведения; пауза и закрытие
останавливают обновления. Индекс интервалов выбирает все активные реплики,
при перекрытии автоскролл ведёт к первой в порядке отображения.

CJM: найти запись -> открыть -> прослушать спорную фразу -> назначить говорящего
(одна реплика по умолчанию) -> исправить текст -> сохранить -> экспортировать.
При ошибке аудио остаётся текст; при ошибке сохранения остаётся редактор с вводом.
При переходе на старый TXT показывается режим только для чтения.

### Экспорт

Пользовательский текст реплик, назначенные имена спикеров и контекст календаря экспортируются дословно (verbatim) без лексической очистки (lexical cleaning) и без удаления путей. Лексический сканер и сопутствующие грамматики/таблицы приоритетов полностью удалены из спецификации и кода.

Защита от утечки технических путей, внутренних идентификаторов и диагностических сообщений обеспечивается строгим отбором разрешённых полей (field allowlist):

1. **Календарный контекст** (если присутствует в документе):
   - `title`: выводится первой строкой дословно.
   - `startAt`: выводится в формате `Дата и время: <startAt>` дословно.
   - `timeZone`: выводится в формате `Часовой пояс: <timeZone>` дословно.
   - `agenda`: выводится в формате `Повестка: <agenda>` дословно.
   - `attendees`: выводится в формате `Приглашены: <attendee1>, <attendee2>` дословно через запятую с пробелом.
   - Отсутствующие или пустые поля опускаются без подстановки вымышленных значений.

2. **Предупреждения о распознавании и обработке** (если присутствуют):
   - Размещаются единым блоком с заголовком `Предупреждения:` перед блоками реплик.
   - Исходное диагностическое поле `warning.message` полностью исключено из экспорта и никогда не выводится, так как может содержать сырые системные пути (`/private/var/...`, пути к временным аудиофайлам) и технические трассировки ошибок.
   - Вместо сырого сообщения код предупреждения `warning.code` статически сопоставляется с фиксированным безопасным текстом:
     - `diarization_voice_limit`: «Достигнут предел распознавания 8 голосов.»
     - `aec_failed`: «Эхоподавление не выполнено; распознаётся исходный микрофон.»
     - `aec_warning`: «Эхоподавление завершилось с предупреждением.»
     - `correction_failed`: «Коррекция терминов не выполнена; сохранён исходный текст.»
     - `playback_mix_failed`: «Подготовка совместного аудио не удалась; доступен только текстовый режим.»
     - `diarization_failed`: «Разделение голосов не выполнено.»
     - `capture_warning`: «Предупреждение захвата аудио.»
     - `recognition_warning`: «Предупреждение распознавания речи.»
     - `context_unavailable`: «Не удалось прочитать контекст встречи.»
     - `recognition_voice_limit_recovery_failed`: «Восстановление после превышения лимита голосов не выполнено.»
     - Любой неизвестный код предупреждения: выводится документированный безопасный общий текст «Предупреждение обработки записи.».
   - При наличии `sourceID` строке предупреждения предшествует локализованная метка дорожки: `[Микрофон] ` для `.host` или `[Системный звук] ` для `.remote`. Если `sourceID` отсутствует (`nil`), префикс дорожки не добавляется.

3. **Реплики**:
   - Таймкод начала реплики в формате `[HH:MM:SS]`.
   - Имя спикера: назначенное пользователем непустое имя из `edits.overrides` выводится дословно. Если переопределение отсутствует для данной реплики (или `displayName == nil`), используется метка `Speaker <displayNumber>`. Переопределения с пустым или состоящим только из пробелов именем строго отклоняются валидацией (`TranscriptExportError.writeFailed`) и не допускаются к экспорту. Допустимые имена, содержащие пути, кавычки или спецсимволы, сохраняются дословно и не сбрасываются на метку Speaker N.
   - Текст реплики: исправленный текст из `edits.overrides` либо исходные слова реплики выводится дословно со всеми пробелами, переводами строк (CRLF, LF, CR), кавычками, апострофами, POSIX-путями (`/tmp/...`, `/Users/...`), путями Windows (`C:\...`, UNC `\\...`) и URL-ссылками.
   - Формат блока: `[HH:MM:SS] <Имя>:\n<Текст>` с разделением блоков реплик пустой строкой `\n\n`.

Служебные поля документа (`schemaVersion`, `resultID`, `createdAt`, пути исходных аудио `sources.originalAudioPath`, `sources.recognitionAudioPath`, `playback.mixPath`, параметры `aec`, служебные ID реплик и слов, каналы) в экспорт не выбираются, что исключает попадание технических путей файловой системы в экспортируемый текст.

Экспорт отдельного TXT строится из выбранного сохранённого результата и его правок.
В начале выводятся доступные название, дата и время с часовым поясом, повестка и
"Приглашены" из сохранённого контекста календаря. Пустые поля опускаются; календарь
не подтверждает присутствие и не назначает имена голосам. Затем идут краткие
предупреждения о распознавании, если они есть, и блоки реплик:

```text
[00:12:34] Дмитрий:
Предлагаю оставить только смешанную дорожку.

[00:12:41] Speaker 3:
Согласен.
```

Таймкод начала реплики сохраняется после редактирования. Неизвестные имена
заменяются уникальными displayNumber. Служебные метаданные и технические пути исключаются
через отбор разрешённых полей и безопасное сопоставление предупреждений; пользовательский
текст и имена сохраняются дословно. Запись поверх исходных аудиофайлов, результата распознавания
и правок запрещена.

Атомарная запись и защита файлов записи:
- Запись во временный файл в том же каталоге с последующим атомарным переименованием (`renamex_np` с `RENAME_EXCL` при запрете перезаписи, `rename` при разрешённой перезаписи).
- Проверка назначения: запрет записи в дерево каталога записи (`recordingDirectory`), проверка `stat`/`st_dev`/`st_ino` для предотвращения перезаписи исходных файлов через symlink или hardlink.

### Проверки

Python: сериализация документа при Parakeet on/off и частичном сбое коррекции,
сохранение перекрытий, уникальная нумерация голосов, публикация результата и микса
версии при AEC on/off, сбой смешивания без потери текста. Swift: декодирование и валидация,
overrides и версии, атомарное сохранение с внедрённой ошибкой, undo, экспорт,
выбор активных интервалов, состояния автоскролла. Синтетические данные для CI.
UAT: реальный звук и seek, исчезнувший файл, светлая/тёмная тема, клавиатура,
VoiceOver, соответствие микса выбранной версии при AEC on/off, перекрытия дорожек, запись на 8 часов и повторное открытие правок.

Для восьмичасового UAT фиксируются модель Mac, объём RAM, версия macOS, число
слов/реплик, размер JSON и аудио, время до доступности текста, задержка seek и
пиковая память. Прогон выполняется офлайн, на локальном диске, с переходами к
началу, середине и концу; результаты холодного и повторного открытия разделяются.
Согласованные сопровождающим пороги: открытие <= 5 с, seek <= 1 с,
реакция управления <= 200 мс после загрузки, прирост памяти приложения <= 1 GiB
от состояния перед открытием. Приёмка проводится на Mac сопровождающего;
точная конфигурация фиксируется в отчёте UAT. Отсутствие падения само по себе
не заменяет проверку этих порогов.

## Risks / Trade-offs

- Таймкоды ASR приблизительны: сверять переходы на реальном аудио, не обещать точности слова.
- Микс каждой версии увеличивает расход диска; исходное аудио и старые версии не удаляются автоматически.
- JSON переписывается при сохранении: писать только overrides, загрузку результата выполнять вне главного потока.
- Переименование группы может заменить ручные назначения: показать число затронутых реплик и дать undo.
- В одной реплике могут оказаться разные люди: разделение реплики отложено, имя не считается доказанной личностью.
- Предложение хранения пока не проверено прототипом: данные и UAT идут до полировки UI.

## Migration Plan

Сначала постоянный документ и тесты совместимости, затем просмотр, затем правки.
Старые файлы автоматически не мигрируются. Старое приложение продолжит читать TXT
и игнорировать новый каталог; откат не удаляет документы. Публикация релиза отдельно.
