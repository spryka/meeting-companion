# Swift/MLX-конвейер без Python

## Why

Полный MLX-конвейер уже работает через Python, но приложение по-прежнему готовит
Python, uv и пакеты. Нужен нативный конвейер с отдельно скачиваемыми весами и
полностью локальной работой после подготовки. Ускорение и снижение памяти
проверяются экспериментом и не обещаются.

## What Changes

- Отдельный завершающийся Swift worker для обработки одной записи. UI и захват
  не загружают MLX и веса моделей.
- Проверяемые SwiftPM-границы: контракты и хранение, сценарии приложения,
  macOS-адаптеры, конвейер worker и UI. Очередь и состояние обработки принадлежат
  сценариям приложения; UI отображает их и передаёт команды.
- Обработка по моделям: Nemotron → VAD → GigaAM → Parakeet, внутри каждого
  этапа host → remote с одной загрузкой весов и независимым состоянием дорожек.
  Перед следующей моделью предыдущая освобождается. Исходный GigaAM с назначенными
  спикерами сохраняется до необязательной коррекции Parakeet.
- Готовые GigaAMKit, Nemotron из SpeechVAD и Parakeet/Silero из MLXAudio как
  исходные кандидаты. Архитектуры нейросетей самостоятельно не переписываем.
- Закреплённые зависимости, веса, точность вычислений и локальные загрузчики.
  Общий MLX Swift 0.32.3 graph и четыре local loaders проверены в отдельном PoC;
  продуктовые API, упаковка и полный паритет ещё не подтверждены.
- Портирование управляющей логики, сохранение окон 25/24 с, назначения голосов,
  коррекции терминов, результатов, предупреждений и протокола прогресса.
- Последовательное сравнение отдельных моделей, затем полного конвейера с
  замороженным Python baseline. Смена расписания, языка, весов и точности
  измеряются отдельно.
- Только после приёмки сравнения: интеграция, диагностика, подготовка моделей,
  упаковка без Python/uv и подписанная тестовая сборка.
- Основной профиль реализации после PoC: GigaAM F16 weights + F32 FFT frontend
  и activations, Nemotron исходного BF16 checkpoint, Silero v6 F32, необязательный
  Parakeet Q8 с F16 input/dense. F32 GigaAM используется как измерительный control.
  Текущие revisions и профиль — в design; результаты проверок — в verification.
- Ограниченная память VAD без смены масок и исходного PCM; время, RSS и MLX
  измеряются на доступном Mac с фиксацией конфигурации.
- Чтение ASR-окон прямо из WAV без полной PCM-подготовки. Nemotron уже имеет
  stateful network chunks, но PoC удерживает полный PCM/mel; порционная замена
  frontend требует отдельного exact BF16 сравнения. Новые замеры F32 отражены
  в verification, базовый F16 profile не меняется без повторных серий и review.

## Capabilities

### New Capabilities

- `native-transcription-runtime`: Swift worker, локальная подготовка, совместимость
  результатов и тестовая поставка без Python.
- `transcription-parity-evaluation`: воспроизводимое сравнение моделей и конвейера.

### Modified Capabilities

Нет. В `openspec/specs/` нет основных спецификаций. Редактор `transcript-editor`
принят с исключениями и включён в `master`; его формат и поведение сохраняются.
Исторический full-MLX Python snapshot — reference моделей, а не текущий код приложения.

## Impact

Будущие изменения: `Package.swift`, отдельный worker target, управляющая логика
транскрибации, `Transcription.swift`, диагностика и подготовка, packaging checks,
README, CHANGELOG и THIRD_PARTY. Границы модулей и порядок выделения:
[design.md](design.md#границы-модулей-приложения).
Подготовлены этот OpenSpec change, согласованный ADR-0002 и отдельно
разрешённые console PoCs: `experiments/swift-gigaam-poc` и
`experiments/swift-pipeline-poc`. Проверены полный корпус и варианты оптимизации;
их код не становится продуктовой реализацией автоматически.
Прототипы сами не меняли Package приложения и его исходники. Worktree обновлён
fast-forward до `master` `520f7d3a9d826d14c26380dc502aa3007b531760` с готовым
редактором; native producer должен формировать JSON v1 для существующих reader/UI без миграции.
Сохраняются аудиопревью истории (`<base>.m4a`) и микс выбранной версии редактора;
подробный контракт — в [design.md](design.md) и specs.

Захват микрофона, системного звука, мьют и алгоритм AEC не входят в изменение.
Сохраняются `local.meeting-companion`, storage paths, подпись приложения и данные.
Python baseline остаётся вне поставки. Публикация и установка не входят в приёмку.

Материалы: [baseline](baseline.md), [исследование](research.md), [design](design.md),
[ADR review](adr.md), [задачи](tasks.md), [проверки этого этапа](verification.md).

## Approval Gates

1. Владелец разрешил актуализацию и начало реализации 2026-11-02 в прежней
   границе отдельного worker. Разделение модулей
   [ADR-0003](../../../adr/0003-separate-application-from-ui.md) принято владельцем
   2026-11-02 вместе со спецификацией и запуском выполнения через sdd-orchestrate.
2. Проверка toolchain, зависимостей и отдельных моделей. Если для совместимости
   потребуется собственная архитектура или непроверяемая замена модели, остановка
   и уточнение плана, без автоматического расширения задачи.
3. Приёмка отчёта сравнения перед подключением worker к приложению. Значимые
   расхождения нельзя принять молча; по умолчанию действуют строгие критерии specs.
   Для текущих pinned revisions проверяются новые результаты и совместимость
   с редактором/превью.
   Поддерживаемый Parakeet timing API остаётся продуктовой задачей.
4. Подписанная тестовая сборка предоставляется отдельно. Установка и релиз требуют
   отдельной команды пользователя.
